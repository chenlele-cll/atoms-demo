# Design

## Context

动机和范围见 [proposal.md](./proposal.md)，行为契约见 [bounded-generation](./specs/bounded-generation/spec.md)。当前后端只有健康、监听和配置模块，没有真实模型客户端、数据库或项目工具。GEN-001 的模板、GEN-002 的客户端及 GEN-003 的存储均为待实施依赖，不以其规划完成状态代替运行证据。

[产品方案](../../../docs/product/core-paths.md) 已选定“基于现有官网模板做业务改造”，首轮不做自动诊断修复。模板使用提前编译的 Tailwind CSS，模型新增样式需使用普通 CSS；模板依赖和启动方式保持固定。GEN-004 只形成可被后续 HTTP 层调用的生成内核和本地验收入口。

## Goals / Non-Goals

**Goals:**

- 将单步模型传输、受限工具、文件合并和事务保存分开，使步骤上限和失败行为能够独立验证。
- 生成依赖已存当前快照，真实读取结果参与模型后续请求，文件修改可检查且旧版本保持可用。
- 使用已有 Node 测试器验证完整模型协议与数据库链路，真实调用单独执行并清楚标记来源。

**Non-Goals:**

- 不新增公开生成路由、SSE、取消路由、项目级队列或跨进程调度；这些由 GEN-005 接入。
- 不编译或执行生成代码，不将保存成功当成预览通过；GEN-006 负责候选加载与采用，GEN-010 负责真实业务交互验收。
- 不新增 Agent 框架、shell 工具、任意 HTTP 工具、补丁解析器、自动重试、修复循环或备用模型。

## Decisions

### 1 以内部生成入口组合已有模块

计划新增 `backend/src/generation/` 中的契约、上下文/策略、工具与编排具体模块。入口接受服务端会话标识、projectId、baseVersionId、requestId、prompt、AbortSignal 和可选活动观察回调；不接受代码、依赖、任意模型配置或工具列表。服务端校验会话到期与项目归属，不能仅因参数来自内部调用就跳过归属检查。

请求 ID 和项目/版本 ID 使用 UUID；prompt trim 后非空、最多 4000 字符且 UTF-8 不超过 16 KiB。先校验输入和归属，再查询已有同 requestId 记录；匹配的重复请求返回原结果，新增请求才检查基线是否仍是 currentVersionId。这样后续采用新版本后，旧请求仍可安全重放其原结果，不会重新计费。

模型配置沿用 GEN-002 的懒初始化，不影响健康、项目读取和服务启动。新请求在模型配置与基线校验完成后受理；预检失败不创建运行，受理后错误则保留原始用户需求。所有源文件、来源和依赖来自数据库，模板 catalog 仅用于核对当前支持的修改策略，不用它替换项目快照。

选择内部入口而非临时同步 HTTP API，是为了避免 GEN-005 再维护第二套请求生命周期。GEN-004 的验收通过测试与独立 CLI 进入同一个内核；未来公开路由仍须先经过 GEN-003 的 cookie、Origin 和限流边界。

### 2 使用显式有界循环，复用 SDK 的协议处理

GEN-002 客户端提供一次模型工具请求所需的受控 SDK 能力，本次编排逐步调用它，最多 6 次。每次请求设置 `maxRetries: 0`、共享取消/截止信号和既定输出 token 上限；不同时开启 SDK 自动多步执行。模型必须调用工具，普通描述文本不作为文件提交；拒绝、截断或缺少合法调用立即结束。

使用 Zod 作为工具输入唯一 schema，派生供应商结构，所有对象严格拒绝额外字段，所有工具参数为必填。供应商请求明确启用 strict 并关闭并行工具调用，仍在应用端再次检查工具名称、参数、唯一调用 ID 及每步调用数量。官方 [OpenAI 工具调用文档](https://developers.openai.com/api/docs/guides/function-calling) 说明 strict schema 的字段要求及 `parallel_tool_calls: false`；这些协议设置不替代服务端文件策略。

只公开以下三个工具：

| 工具 | 输入 | 实际行为 |
| --- | --- | --- |
| `list_files` | `{}` | 返回基线的排序路径、字节数和可修改标记，不读取宿主目录 |
| `read_files` | `{paths:string[]}` | 从本轮冻结基线返回 1–8 个不同文件的完整文本，合计不超过 96 KiB，并记录已读取路径 |
| `submit_files` | `{files:{path:string,content:string}[]}` | 校验 1–8 个文件，在内存合并/校验完整候选，再交由编排保存；仅允许一次终端提交 |

目录/读取工具的结果与对应调用标识加入下一次模型输入，保留 SDK 支持的响应续接信息，不手工只保留纯文本而丢失必要协议项。OpenAI 文档要求推理模型的相关响应项随工具结果续接；必要续接元数据只留在本轮内存，不作为产品活动、日志或数据库对话公开。SDK/HTTP 测试要验证这一点。

提交是终端动作，校验和保存完成后直接结束，不为“确认已保存”再付费请求模型。工具错误立即终止，不回送一个错误后继续自动修复。工具无 execute 权限扩展点：其实现闭包只持有快照与策略，不获得数据库句柄、环境对象、文件系统、fetch 或子进程能力。

### 3 修改策略采用允许范围，完整文件提交后再合并

新增 `company-landing` 的具体策略，不做通用插件系统：已有业务文件只允许 `/App.tsx`、`/src/App.tsx`，以及根目录或 `/src/` 下 `components/`、`data/`、`lib/`、`generated/` 中的 `.ts/.tsx`。新文件仅允许 `/src/generated/` 下的 `.ts/.tsx/.css`；本轮生成后再修改的 generated CSS 也属于此范围。目录工具为每个实际文件标注策略结果。

其他文件只读，包括启动引导、配置、JSON 清单、许可、资源和已编译 CSS。基线必须含有可修改业务文件，否则预检返回不支持的模板布局，不扩大权限兜底。策略覆盖根路径和 src 路径两种布局，实施用 GEN-001 的真实 bundle 作为接入测试输入，而不假设上游源文件可以直接运行。

路径复用 GEN-003 的规范化规则，拒绝 `..`、反斜杠、NUL、编码绕过、非规范虚拟路径和重复路径。提交前至少成功读取过一个文件，对已有文件的覆盖要求该路径已由本轮 read_files 成功读取；只允许新增或替换，不支持删除。正文必须非空，提交正文合计最多 256 KiB。先校验整个提交，再复制基线文件映射并应用全部变更，不逐个落盘。

合并后复用快照 schema 检查入口存在、64 文件/2 MiB 限制、固定依赖与来源；不允许模型提交或改变这些元数据。服务端按实际内容计算 changedFiles 和新摘要，拒绝完全无变化的提交，不能相信模型自己声称修改了哪些文件。新快照 parentVersionId 指向本轮基线。

提示词要求复用已有布局和组件、用普通 CSS 完成新增样式、不新增依赖、不冒充真实表单提交或支付。用户需求和代码内容作为数据传入，不改变工具权限。文件 schema 和依赖元数据检查不证明 TSX 语法、代码行为或网络安全；后端不执行这些代码，实际 import、编译与交互在隔离预览验收，不使用字符串检查伪装编译通过。

### 4 上下文和资源预算在每步执行前检查

初始输入包含固定系统规则、当前需求、模板/入口/依赖元数据及同项目最近的完整对话。历史最多 10 条且总正文不超过 16 KiB，按从近到远选择后恢复时间顺序；超过预算的历史整条排除，记录省略条数，不截断源文件或将旧候选错误当成当前代码。当前需求只加入一次。

每次请求前按 UTF-8 序列化后的工具 schema 与消息计算上下文上限 256 KiB；目录和读取结果加入后也检查下一步预算。受限内容不能靠截断后继续。文件正文上限只是存储/传输限制，不能使模型绕过 GEN-002 的输出 token 限制；输出截断失败后不自动增加预算。

| 边界 | 默认及规则 |
| --- | --- |
| 模型请求 | 最多 6 次，每次最多执行一个工具调用，无 SDK/业务自动重试 |
| 总截止时间 | 复用 MODEL_TIMEOUT_MS，默认 0 不设累计期限；显式正值才计时，范围沿用修订后的 GEN-002，往返不重置显式计时 |
| 输出 token | 复用 MODEL_MAX_OUTPUT_TOKENS，默认 4096，允许范围沿用 GEN-002，每次请求明确传递 |
| 上下文/工具/快照 | 按规格的 256 KiB、96 KiB、256 KiB、64 文件/2 MiB 分层限制 |

使用单调时钟和组合 AbortSignal；每次请求、工具执行、候选验证与成功事务前检查。配置显式正期限时，事务返回前再次检查截止时间，超时则抛出并回滚，防止数据库等待跨过期限后仍报成功。清理和失败记录写入为有界收尾，不承诺供应商收到中止就一定免除在途费用。

### 5 两段短事务区分受理与成功，保留失败输入

扩展 GEN-003 的具体存储操作，而非另建数据库。受理事务再次检查归属、当前版本与 requestId 唯一性，同时插入 running 记录及关联的 user 消息；模型调用在事务外。唯一约束冲突后读取已有记录并比较基线/原始需求，相同则返回已有状态，不同则 REQUEST_CONFLICT，不创建第二条消息或调用。

候选保存事务再次确认运行仍为 running、项目当前版本未变化，并原子插入完整候选、关联的 assistant 完成摘要及 succeeded/resultVersionId/finishedAt。完成摘要由服务端根据实际 changedFiles 和保存结果生成，明确“候选已保存、预览未验证”，不采用模型自行声称的编译或业务验收结论。事务不更新 currentVersionId。

若生成过程中基线已变化，返回 BASE_VERSION_CHANGED，不保存候选。相同请求重放时从已存快照及基线重建实际修改列表；失败重试使用新的 requestId。本次只保证请求唯一性及提交一致性，不实现 GEN-005 的项目级并发准入、排队或取消路由。

失败结束已有 run：外部取消写 cancelled，超时写 failed + GENERATION_TIMEOUT，其余复用模型安全分类或文件/步骤/存储分类；不插入完成摘要和半成品候选。成功事务失败后若存储仍可写，再独立写安全终止状态；若连终止状态也不能写，返回 STORAGE_UNAVAILABLE 和 terminalStatePersisted=false，不能声称数据库已终止。用户消息与旧当前版本保持不变。

取消在成功提交前生效则禁止保存；成功事务先提交则结果固定，晚到取消不能反向改状态。正常异常走 finally 结束监听与计时。进程被硬杀后可能留下 running，GEN-005 再接入启动恢复/interrupted 处理；本任务不承诺后台续跑或崩溃后的自动模型重试。

### 6 活动和结果向后续调用方提供事实摘要

内部活动仅有请求开始/结束、工具开始/结束、候选校验、候选已保存及运行终止，含 runId、单调序号、时间、步骤、工具名、字节数、修改路径或安全错误码。仅在实际动作发生后发出相应完成活动；saved 在事务提交后发出。观察回调失败记录安全诊断，不改变已提交的数据结果。

返回结果包含 runId、baseVersionId、candidateVersionId、服务端计算的 changedFiles、保存事实摘要及 `previewStatus: unverified`。复用 GEN-003 的 succeeded 表示候选生成/保存完成，不能作为 UI 的“可运行”依据。失败只返回安全分类及持久化确认信息。必要的模型续接项、提示词、代码和工具正文不进入活动或普通日志。

用量按实际已观测请求汇总，任一步缺失时总量为 null，保留已观测分项而不报零费用；请求次数按实际发出记录。重放或重启后没有持久指标时返回 null，不能把历史用量记成零。本次不为这些观察指标扩表。fixture/live/not-run 由验收运行器标记，不给生产服务增加假模型配置。GEN-005 将这些内部活动映射为公开事件时再定义 HTTP schema、断线和缓冲边界，本任务不维护平行事件协议。

### 7 自动化穿过 SDK 与 SQLite，live 验收独立执行

测试继续放在 `backend/test/*.test.ts`，由 Node 测试器和 pnpm check 运行。依赖注入用于受控传输、时钟与观察者，不建立通用服务容器，也不在生产配置中暴露假供应商地址。

| 层次 | 关键验收 |
| --- | --- |
| 策略/合并 | 真实模板 bundle、只读文件、路径绕过、重复路径、未读覆盖、无变化、体积、保留未改文件、依赖/入口不变及重新计算摘要 |
| SDK/工具往返 | 本地随机端口受控 Responses 服务，通过实际 GEN-002 客户端观察 list/read/submit；断言读取的独特内容出现在后续请求、协议续接项保留、strict/串行参数、未知工具和多调用拒绝，无隐藏重试 |
| 存储集成 | 每例真实临时 SQLite 文件，受理/成功关联、失败回滚、相同请求不二次调用、不同需求冲突、基线变化拒绝、关闭重开候选且 currentVersionId 未变 |
| 生命周期 | 延迟响应时取消/超时，观察底层请求中止；取消后晚到提交、提交后取消、步骤/上下文耗尽，均不额外调用或产生矛盾终态 |
| 隐私与持久化故障 | 含哨兵的原始错误、提示词和工具正文不进入日志/错误；候选写入失败与终态更新失败分别验证，不能用内存成功代替落盘 |
| CLI 子进程 | 帮助零请求、缺凭据 not-run 且非成功退出、构建入口可用、实际信号取消与资源释放；fixture 不算 live |

新增 `backend/src/generation/smoke.ts`、源码 `generation:smoke` 与构建 `generation:smoke:built`，根目录增加同名源码转发。均为计划命令，当前不存在；无参数/--help 只显示说明，真实执行需 `--live --case quote|filter`。使用固定公开样例需求，分别要求新增报价估算或案例筛选；每次只运行指定一例，不自动执行第二例或补跑失败请求。

运行器创建自己的随机隔离目录、有效匿名会话及新模板项目，直接调用同一生成内核；不接受开发者现有项目 ID 或数据库路径，忽略环境中的生产 DATABASE_PATH。关闭再打开自有文件，比对完整候选和旧当前引用；不通过复制或改写生产数据准备样例。信号转发给内核后进行有限清理，不继续下一轮。

报告只包含来源、实际模型、时间、请求次数、用量、运行/版本标识、修改路径、摘要散列、保存和重开结果以及安全错误码，不输出代码、提示词、凭据或供应商原始响应。证据放入忽略的 `test-results/generation-smoke/`；默认日志不含内容，隔离数据库作为本地测试产物不上传。实际供应商请求发出才标 live；预检失败是 not-run；成功也只证明候选生成与持久化。

默认 check、smoke、verify 和 CI 均不自动运行 live。live 最终验证优先执行构建入口的一例，复用同一次真实调用证据，不为了重复证明源码入口另付费。没有凭据时可完成自动化和构建验证，但真实验收任务保持未完成；两个真实需求及其桌面/窄屏交互仍在 GEN-010 收口。

## Risks / Trade-offs

- 6 步、显式有限期限或输出预算不足以完成某需求 → 明确超限原因，优先控制单次业务改造规模；不隐式加预算或扩展修复循环。
- 现成 Tailwind 样式覆盖不到新增类名 → 提示词和样例使用普通 CSS，真实预览仍是后续独立验收。
- SDK 续接信息处理错误导致工具往返失败 → 受控 HTTP 集成检查实际后续请求，并用单独 live 运行确认选定模型能力。
- schema 合法仍可能代码有误或需求未实现 → 所有输出保持 unverified，编译和关键交互通过后才能由后续功能采用。
- 存储不可写或进程被硬杀导致终态未知 → 返回未确认状态、保留原当前版本，不谎报完成；GEN-005 负责运行恢复和公开状态处理。
- 与其他变更同时修改客户端、存储、脚本 → 实施前重新读取 GEN-001～003 实际代码，按本变更边界接入并保留他人修改。

## Migration Plan

1. 完成 GEN-001～003 所需实际代码后，接入生成契约、固定策略及单步模型能力；先跑策略和协议失败测试，不需要真实密钥。
2. 连接受理与候选完成的短事务，使用临时文件验证所有终态、重复请求及关闭重开；现有项目 API 行为保持通过。
3. 接入源码/构建 smoke 和脱敏报告，更新 README、Development、Verification 中的实际入口、限制和边界；不改写先前 change 的历史记录。
4. 运行 pnpm check、pnpm smoke（含 build）、GEN-003 的项目恢复回归及严格工件校验；生成内核不改变监听入口，只有实际触及生命周期代码时再补对应 manager 回归。
5. API 已准备好时显式运行一次构建后的 live 样例并记录结果；未准备好时保留未验证状态。上线与浏览器最终验收留在 GEN-009/010，不在此执行。
6. 回退仅停用生成入口和撤回相应应用产物，保留所有项目、消息、运行与候选；本变更不需要破坏性数据库迁移。后续采用只操作已验证的独立候选，原快照不会被覆盖。
