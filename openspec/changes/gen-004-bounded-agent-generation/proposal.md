# Proposal

## Why

GEN-001～003 分别规划了可运行模板、模型调用和项目存储，但还缺少把用户需求变成真实业务代码的生成编排。`GEN-004` 建立单个受约束 Agent，从已有项目快照出发，通过实际文件读取与提交工具生成并保存独立候选，为后续流式交互和预览提供可调用的内核。

## What Changes

- 复用 GEN-002 的服务端模型客户端和 GEN-003 的归属、快照与生成记录；生成只能读取指定项目的已存基线，不接收浏览器提供的替代文件或凭据。
- 提供文件目录、批量读取和一次性提交修改文件三个有限工具。修改采用完整文件内容，服务端合并为完整候选快照；不实现文本补丁协议、宿主目录访问或命令执行。
- 为模型请求数、总时限、上下文、读取和提交体积设置明确上限；无自动重试、自动修复、多 Agent 或模型切换。未知工具、非法调用、拒绝、截断和未提交结果均不能算成功。
- 在模型调用前保存用户消息与运行记录；仅在候选全部校验并原子落盘后保存完成摘要和成功结果。失败保留用户输入和原当前版本，取消及超时停止后续步骤并丢弃晚到结果。
- 生成结果标为未预览验证的候选，不改变项目当前版本。活动摘要来自实际请求、工具、校验和存储，不展示思维链或模拟进度。
- 增加无真实凭据的自动化集成测试，以及单独显式执行、使用隔离项目的真实生成 smoke；区分 fixture、live 和 not-run 证据。
- 本轮只生成规划。生成内核及本地验收入口属于 GEN-004；公开生成/流式/取消接口与并发管理由 GEN-005 接入，候选预览与采用由 GEN-006 接入，工作台和完整真实端到端验收由后续任务完成。

## Capabilities

### New Capabilities

- `bounded-generation`: 在已有项目和明确资源边界内，通过真实模型工具往返提交、校验和持久化候选业务代码，并保证失败不覆盖当前版本。

### Modified Capabilities

无。当前没有已有长期规格；本变更消费 GEN-001～003 的规划契约，不改变其模板、模型探针或项目基础接口范围。

## Impact

- 后端新增生成契约、模板修改策略、工具、编排和候选持久化接入；保持路由、模型传输、数据库与生成职责清楚。
- 复用既定 AI SDK、OpenAI provider、Zod 和 SQLite，不引入新的 Agent 框架、队列、代码执行服务或前端运行依赖。
- 新增本地生成 smoke 的源码/构建入口及脱敏报告；默认 check、smoke 和 verify 不调用真实模型，也不启用生产假模型开关。
- 更新实施涉及的 Development、Verification、README 等 owning 文档；本次不新增公开 HTTP 契约、工作台 UI、编译服务或线上部署操作。
- 实施依赖 GEN-001 和 GEN-003 的实际模板/存储，以及 GEN-002 的可测试客户端；live 验收还需要真实 API 配置与工具能力通过记录。
