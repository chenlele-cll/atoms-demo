# Context

manager 当前静态导入 proper-lockfile，干净克隆尚无依赖时不能直接用来初始化。Process Compose 的官方安装器已经包含平台选择、发布下载与 SHA-256 校验，可直接复用而不另写下载协议。

# Goals / Non-Goals

- 目标：可重复 bootstrap、明确 doctor、按服务 logs，与现有起停核心协作。
- 非目标：自动安装全局 Node/pnpm、自动升级、重写安装器、基础设施、产品功能或日志平台。

# Decisions

- shell 将 bootstrap/doctor 路由到只依赖 Node 标准库的工具入口。Node/pnpm 版本由现有文件指定，bootstrap 版本不符时先失败，不修改全局安装。
- 原样保留 Process Compose `v1.122.0` 源码提交 `673850dd20683ef14b33890444ca3416d02c751c` 的官方 get-pc.sh 和 Apache-2.0 LICENSE。明确传入项目固定 tag，在私有临时目录安装，校验实际版本后原子移入 `.tools/`；已有匹配工具保持不变，不覆盖不明损坏内容。
- bootstrap 只执行 frozen install，不创建或覆盖 .env、不启动服务、不改声明或 lockfile。运行前要求没有 manager 实例记录；首次依赖安装不承诺与另一安装命令并发，安装交给 pnpm。下载/安装有整体期限，中断清理本次临时目录和子进程。
- doctor 汇总版本、声明依赖、配置、workspace、可选环境文件及端口/实例状态，支持 JSON。没有服务运行且端口空闲是正常状态；活动实例不健康或外部占用明确失败。不读取或输出环境变量秘密，不在诊断中启动、停止或安装。
- logs 只接受 backend/frontend/all；活动实例确认归属后复用官方 CLI 读取与跟随。停止后只读取当前本地应用合并日志，按服务和行数限制，不跟随失效实例，不读状态、认证或环境文件。
- 日志继续遵循应用产生日志时的既有规范，不将读取器描述为通用秘密扫描器。当前管理认证值如进入输出可遮盖；不输出认证元数据。
- 保留已有核心命令与状态语义；补充帮助、文档与行为测试，不创建新 Skill。

# Risks / Trade-offs

- bootstrap 首次需要网络、Node/pnpm 和官方安装器所需的 POSIX 工具；不能把缺少环境前提视为初始化成功。
- 原生在线日志和本地当前文件有不同保留范围；不宣称可检索所有归档历史。
- 只在本机 macOS arm64 实测，其他平台、离线新机器与生产环境不能据此宣称可用。

# Migration Plan

增加入口后验证干净副本、重复运行、错误版本和校验失败；真实启动并读取/跟随日志，确认停止跟随不影响服务。交付前停止验证实例并保留其他任务的改动。
