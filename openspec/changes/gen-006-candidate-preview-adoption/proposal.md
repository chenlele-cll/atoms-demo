# Proposal

## Why

GEN-004/005 产出的是已保存但尚未预览验证的候选，当前版本不能随生成成功自动变化。`GEN-006` 让所有者读取候选、在隔离浏览器预览中检查，再明确采用为当前版本；编译、网络或采用失败时保留原版本，并避免旧预览回调与多标签页竞争造成误报。

## What Changes

- 新增有归属的不可变版本读取与候选采用接口；候选必须关联本项目成功运行，采用以预期当前版本做原子比较，不能覆盖另一标签页的新选择。
- 复用 GEN-001 的 Sandpack 适配与固定依赖，抽取可复用的完整快照预览组件；文件仅在独立跨源 iframe 运行，不导入宿主 React 树或在后端执行。
- 提供聚焦候选检查的页面，显示候选/当前版本、来源、实际修改文件、加载/编译/运行错误与重试；可切换查看当前版本，待本轮预览编译完成并由用户明确点击后采用。
- 将预览状态绑定到项目、版本、摘要和本轮实例；切换、重试、超时与卸载取消旧请求/监听，过期成功或错误不能影响新版本。
- 明确浏览器编译反馈是本次本地观察，不是服务端可信编译证明，也不代表业务交互已验收。采用接口验证结构、归属、成功运行和基线，不接受客户端 verified 标记，不新增服务端代码执行。
- 采用成功后持久化当前版本引用，刷新及后端重启读回同一版本；失败、冲突或响应丢失有明确查询确认路径，不把本地按钮状态当成保存成功。
- 出现实际前后端共同消费的项目/版本契约，将必要公开 schema 提取为中立 workspace 包；不复制规则、不暴露后端实现，同步必要构建与隔离测试前提。
- 使用明确的测试候选完成真实编译、交互、错误、访问隔离、采用竞争和重启恢复验收；默认不调用模型。完整聊天工作台、历史恢复、分享和真实生成验收仍由后续任务承担。
- 本轮只生成规划，实施依赖 GEN-001、003～005 的实际代码，不因预览能运行而宣布完整 Top 1 已通过。

## Capabilities

### New Capabilities

- `candidate-review`: 在项目归属下读取并隔离预览不可变候选，区分本地预览与持久化状态，由所有者明确采用并保护当前版本及并发修改。

### Modified Capabilities

无。当前没有已有长期规格；本变更实现先前预留的预览/采用边界，不改变生成成功仅表示候选落盘的含义。

## Impact

- 前端：版本 HTTP 客户端、共享快照预览状态机、候选检查页及样式，复用模板预览；遵循现有设计 skill，不提前实现完整工作台。
- 后端：版本读取/候选采用路由、条件事务与活动运行检查；复用会话、Origin、安全错误、SQLite 和单服务所有权，不增加编译进程或容器。
- Workspace：新增最小公开契约包及必要构建接入，前后端显式依赖；仅移动实际共用 schema，模型、存储和业务工具仍留后端。
- 验证与说明：扩展真实浏览器、数据库和 HTTP 失败回归，更新 README、Monorepo、Development、Lifecycle、Verification 及必要的隔离 fixture；不新增测试框架或真实模型调用默认入口。
