# Design

## Context

动机见 [proposal.md](./proposal.md)，行为契约见 [project-workspace](./specs/project-workspace/spec.md)。当前 App 只有连接检查，main.tsx 已启用 StrictMode；前端没有路由、项目客户端或工作台。GEN-001～006 都是待实施依赖，其中 GEN-006 先提供中立契约包、快照预览、采用控制及前端 Node 测试入口。

工作台组合这些实际能力，不重写生成内核、SSE 服务、数据库或 Sandpack。产品仍按 Top 1 优先，历史恢复与分享不在本任务中；本地受控 UI 验收也不代表真实模型或最终部署通过。

## Goals / Non-Goals

**Goals:**

- 提供从模板/需求到项目、真实任务、候选检查、明确采用与重开的连贯交互。
- 以项目/请求/版本身份组织状态，阻止重复计费、跨项目晚到更新和当前/候选混淆。
- 保留故障后的输入与服务端事实，使用已有工具验证浏览器和运行中服务的实际行为。

**Non-Goals:**

- 不实现账号注册、项目删除/重命名、供应商选择、源码编辑、Diff、历史恢复、分享或发布按钮。
- 不引入路由/全局状态管理框架、后台续跑、活动历史重放或新的测试框架。
- 不把客户端缓存、源码展示、模型 succeeded、浏览器 compiled 和采用确认合为一个成功标记。

## Decisions

### 1 轻量路由与分区状态，不在挂载时发送生成

新增实际需要的 creation/workspace 组件及项目、消息、生成客户端。用 React state/reducer 和具体控制 hook 管理状态，不构造通用事件总线或服务容器。导航用现有轻量路径分支扩展 pushState/popstate：

| 路径 | 内容 |
| --- | --- |
| `/` | 真实创建入口与当前会话最近项目 |
| `/projects/:projectId` | 工作台，直接访问和刷新均读取真实项目 |
| `/projects/:projectId/candidates/:versionId` | 保留 GEN-006 独立候选检查页 |
| `/templates/company-landing` | 保留 GEN-001 原模板基线 |
| `/diagnostics/connection` | 迁入原连接检查，保留原行为和独立样式 |

未知路径显示明确不存在状态，不悄悄回到某项目。导航保留普通链接的键盘、新标签页与修改键行为；同页项目切换使用 SPA 导航。每次项目进入产生 activation 标识，异步结果必须同时匹配 projectId/activation，生成再匹配 requestId/runId，预览沿用 GEN-006 的版本/摘要/attempt。

生成仅由明确用户命令调用，不写入 mount/effect。创建并生成是同一用户命令中的串行步骤，不能靠“检测到草稿”或 URL 参数自动发送。保留 StrictMode；[React 官方说明](https://react.dev/reference/react/StrictMode)明确其开发期额外运行 effect，因此用纯状态和幂等初始化解决问题，不以关闭该检查掩盖重复请求。

### 2 会话、目录、项目创建各自有确认边界

首页初始化会话采用应用级 single-flight，避免 StrictMode 的订阅/清理造成两次并发会话创建；初始化不绑定短命组件的重复 effect 清理。成功后读取项目，目录可独立读取；只有真实目录可选、会话可用时允许创建，后台失败不清空输入。示例仅填入需求文本。项目名可编辑，空白默认“新项目”，不为取名另调用模型。

私有项目直达先 GET 项目，不自动 POST 新会话。401/404 显示不可访问，不认领缓存项目；首页明确重新开始会话时才重置初始化状态。新会话 201 或会话失效时清除旧私有缓存和待确认请求，保持不同归属边界。cookie 仍由浏览器管理，不读 HttpOnly 值。

“创建并生成”先 POST 项目，确认返回 ID/初始快照后打开工作台，再显式发送一次原需求；创建未完成时阻止重复点击。若创建完成前用户已离开，不强制跳回或启动模型，项目保留在实际列表。模型缺配置/限流时显示“项目已创建，生成未受理”，保留需求和模板 v0。

GEN-003 创建接口没有请求幂等标识，本任务不增加隐含重试：超时或解析失败只能说结果待确认，刷新最近项目供用户选择，不能按相同标题自动认定是本次项目或自动重新创建。保留输入供用户继续，不宣称创建失败已回滚。

### 3 共用 schema 与兼容消息分页满足实际读取

把实际消费的会话、目录、项目列表/创建、消息、公开 run/SSE 契约移动到 GEN-006 的 @atoms/contracts；原后端引用改为该权威定义，不复制规则或移动私有存储/模型代码。沿用 GEN-006 的准备、构建和 JSON 客户端边界，普通请求 10 秒超时，响应有界，原始错误不直接进入 UI/日志。

大多数 API 沿用 GEN-003/005/006，仅做以下兼容补充：

| 补充 | 契约 |
| --- | --- |
| 项目 latestRun | 确保摘要含 runId、requestId、baseVersionId、resultVersionId/null、status、安全 errorCode 和时间；不含需求/工具正文 |
| `GET .../messages?direction=backward&limit=50` | 首次取最新一页，items 仍按序号升序，返回 nextBeforeSequence/null 与 latestSequence |
| `GET .../messages?direction=backward&beforeSequence=N&limit=50` | 取 N 之前最近一页，仍升序返回；游标为安全正整数，单页 1–50 |
| 原 afterSequence 模式 | 无 direction 时继续原向前增量查询与响应，不改变既有调用方行为；与 backward/before 参数互斥 |

后端使用同一归属条件和绑定 SQL，读取最新页/游标信息保持一致，不需要新表。新的方向分支有独立响应 schema，复用同一 message schema；不能同时接受互相冲突的查询字段。前端初始只取 50 条，点击“加载更早消息”再取一页，按持久 ID/序号合并并保持阅读位置；不自动抓取全历史。

accepted 前需求保留在提交状态中，不能当成已保存消息。accepted 确认后可临时显示该需求，并立即用增量/最新消息校准，通过 runId/角色再对齐持久 ID，防止双气泡。完成摘要来自已存 assistant 消息；失败/取消显示任务状态卡。持久化历史不包含旧工具事件时，只显示已有消息和最新运行摘要，不生成假活动。

### 4 POST SSE 用成熟解析器加应用校验

前端新增固定 eventsource-parser@4.1.2，已核对其 MIT、无运行依赖及 Node >=22.12 元数据，与项目 Node 22.22.2 相容；实施仍做 frozen install、类型和浏览器构建验证。它只处理 SSE 格式，不代替业务 schema，也不负责自动连接。[上游说明](https://github.com/rexxars/eventsource-parser)提供 createParser、注释处理和 maxBufferSize。

使用 fetch POST，Accept 为 text/event-stream，same-origin cookie，保留 GEN-005 requestId/baseVersionId/prompt。根据 Content-Type 区分新流与 200/202 JSON 重复结果，JSON 分支不能丢进 SSE 解析器。错误和 schema 不匹配均安全结束，不自动重发 POST。

流通过增量 UTF-8 解码及解析器处理 CR/LF、跨块和注释。设置 parser maxBufferSize=8192 字符，完成业务数据再检查 UTF-8 8 KiB；总接收上限 320 KiB，业务帧最多 128，与 GEN-005 限制配合并容纳心跳。只接受 accepted/activity/terminal，accepted 必须在先且 seq=1，后续严格递增；项目/request/base/run 关联一致。协议游标在本流实例内同步推进，不依赖 React 下一轮 render，确保同一网络块包含多事件也正确。未知、重复、乱序或非法 JSON 帧中止流并查询原状态，终态消费一次后不能被后续回调改写。

计时与 JSON 请求分开：响应头最多等 10 秒，流读取无数据最多 25 秒，按 2026-10-18 用户修订，默认不设置总连接期限，持续心跳可等待长任务；GEN-005 每 10 秒心跳维持等待但不算进度。超限释放 reader、计时器和 Controller，进入结果待确认，不把 EOF 当成功。解析错误只映射安全分类，不能打印其可能包含正文的原始 error/line。

### 5 请求身份、取消和恢复只以服务端结果收口

每次明确新生成前建立 requestId，在操作生命周期内固定 payload。运行状态为 submitting/active/cancelling/checking/terminal/unknown，与预览和采用状态独立；提交中锁住重复动作。已确认 failed/cancelled/interrupted 后由用户明确重新生成才分配新 requestId，未知请求不自动变成新尝试。

为刷新恢复，在 sessionStorage 的项目命名空间保存有界待确认信封：projectId/requestId/baseVersionId、原需求和时间，不含 cookie、密钥、对话或代码。每项按输入规则限额、最多 20 项，24 小时过期；确认终态后清理。显示本地信封前先验证项目访问，新的会话或 401 清理旧私有数据。存储不可用时退回页面内存并明确刷新恢复限制，不能以它代替服务端保存。普通未提交草稿仅在当前页面内存按项目保留，不承诺刷新持久化。

取消按钮只发取消 POST，202 标记正在取消，原 SSE 继续等实际终态；取消请求失败也不能覆盖同时到达的成功。若流断、EOF 缺终态或 terminal 未确认，按该 requestId GET 查询，而非自动重新 POST。仅恢复 running 时每 2 秒查一次，最多 75 次/150 秒；页面隐藏暂停、离开项目取消，429 尊重 Retry-After，额度/时间耗尽保留 unknown 与“查询结果”。

重开时优先核对本地原请求；另一个标签页的新 latestRun 不能替代它。没有本地记录则使用服务端最新运行摘要，明确这是最新已存任务，不补演事件。running 只查询/取消，不重建流；succeeded 载入候选；failed/cancelled/interrupted 保留输入或真实用户消息并允许明确新尝试；RUN_STATE_UNCONFIRMED 不伪装仍在生成。

404 不等于能证明先前 POST 永远未受理，不自动再次调用。用户明确“重试原请求”时只能使用保存的相同 requestId 和 payload，依靠 GEN-004 幂等；已知终态后的新尝试必须新 ID。刷新和 mount 从不自动执行这类重试。

### 6 工作台保留当前版本，复用候选与只读源码

项目页加载当前快照、最新消息和运行。生成等待时可继续查看现有代码/预览，活动归组到本次需求；候选成功后加载 GEN-006 版本 API，明确标记“候选已保存、未采用”，本地选中候选不会改变 currentVersionId。

复用 GEN-006 的 SnapshotPreview、候选/当前选择、采用可用性、CAS 与 unknown 确认控制；需要时把独立检查页中的具体控制 hook 提取复用，不复制另一套采用逻辑。预览错误保持工作台可操作，可切回当前；采用成功后更新真实项目及列表，下一条需求才基于新 currentVersionId。

输入区明确显示生成基线。若当前查看未采用候选，则先采用或点击“查看当前版本”再提交，不让用户误以为新需求在改这个候选。采用失败/冲突不自动变更 expected；成功后才刷新基线。已有候选仍保留在快照和最新结果入口，不用切回当前模拟删除/放弃接口。

新增只读源码视图：所选快照排序文件列表、当前文件名及普通 pre/code 文本，React 转义内容，无编辑器、HTML 注入或代码执行。切换版本同步文件选择，原文件不存在则选择有效入口；标签始终显示项目/版本。长行只在代码容器滚动，最多已有快照上限，不加入新下载/编辑能力。

同项目切换聊天/预览/代码不卸载任务控制器。可保持唯一预览 iframe 挂载而隐藏以保留临时交互；候选/当前版本切换仍按 GEN-006 新建实例并提示输入重置，不承诺浏览器业务数据保存。

### 7 导航、输入与响应式采用已批准设计

用应用壳和项目状态容器分离路由与视图。项目切换/返回首页先中止所属 GET/流，增加 activation 并忽略旧结果；按 GEN-005 断线规则结束旧生成，不承诺离页继续。生成 Controller 归应用请求控制器所有，视图的 StrictMode 清理只取消订阅，不能把新受理请求当成卸载副作用中止；真正导航只结束旧 activation 的操作。页面退出中止连接，普通隐藏标签仅暂停查询、不取消活动流。A 的 callback 不能更新 B，当前页内不同项目草稿独立，跨会话清理私有内容。

遵循已读取的 atoms-frontend-design：桌面约 240px 项目导航、340–420px 对话、剩余主预览，奶油色面板和炭色操作；中屏先折叠导航，窄屏使用聊天/预览/代码视图。当前项目、查看版本、持久当前版本分别有明确标签，不放未实现的历史、模型选择、分享或发布占位按钮。

输入用带标签 textarea，Enter 换行，显式按钮或 Ctrl/Cmd+Enter 提交，composition 期间快捷键不提交。原生表单提交也遵守组合输入保护；需求长度与 GEN-004 一致。任务状态礼貌播报，不逐条播报心跳；列表/视图键盘可用，触控区域 44px，长标题/路径/错误可读，320/375px 下无宿主横向溢出。

首页从初始化屏明确替换为创建入口。原组件/样式迁到诊断页，旧色板在该页局部作用域保留；新产品语义 token 按 owning skill 落到全局基础，不混用两套变量含义。scripts/smoke.cjs 的连接成功、错误响应、后端离线与恢复场景改去诊断地址，保留原断言；首页增加基本可访问性检查，不因模型未配置触发真实调用。

### 8 验证以用户操作驱动实际链路

复用 GEN-006 前端 Node/tsx 和后端 Node 测试。客户端测试覆盖会话 single-flight、JSON/流分支、UTF-8/行结束跨块、心跳、截断/超限、序号/身份、双终态、取消/查询竞争及清理；状态测试覆盖 StrictMode 语义、A→B 晚到结果、草稿、重复消息、候选基线与 unknown。后端测试同时覆盖 backward 分页及原 afterSequence 兼容，不只测静态 UI 文案。

新增计划 `pnpm smoke:workspace` 和 `scripts/workspace-smoke.cjs`，要求先 build，继续用现有 Chrome/playwright-core。复用 GEN-005 的隔离构建应用启动器与受控 SDK 上游，仅在测试构造中注入传输/假密钥；真实 UI 发请求，生产没有假模型开关。不预填项目冒充创建，不用 page.evaluate 代替主表单操作。

| 场景 | 验收内容 |
| --- | --- |
| 首次路径 | 新上下文初始化、目录、示例只填入、创建并生成；受控 Responses 完成实际工具往返，读取/保存进入 SQLite，真实 Sandpack 编译新增报价控件并操作，明确采用后刷新/重开 |
| 需求与当前基线 | 中文组合输入、换行/快捷键、重复点击、候选未采用阻止误基线；采用后的下一次请求捕获正确 currentVersionId |
| 故障与未知 | 模型未配置/拒绝/限流、创建丢响应、SSE 分块错误/丢末帧、取消 202 与保存竞争、采用丢响应；输入和当前版本保留，无自动计费重试 |
| 隔离与导航 | A/B 归属、同会话多项目、A 迟到结果、页面前进/后退、内部视图切换、刷新取消、跨标签最新任务；验证实际请求次数与持久记录 |
| 对话与源码 | 大于一页消息的最新/更早与增量兼容、无双气泡、不补历史活动；选中版本/文件与实际预览匹配，HTML 源码仅显示文本 |
| 布局与回归 | 1280px、768/1024px、320/375px，键盘、焦点、滚动和错误；dev/preview 两入口，原诊断 smoke 与 GEN-006 候选回归保持 |
| 构建与重启 | 后端关闭/重启恢复已采用版本、对话和 interrupted 状态，保持 cookie/临时 DB，确认没有新的生成 POST 或自动续跑 |

证据写入忽略的 test-results/workspace/，标记 fixture，记录安全请求计数、版本/摘要与截图，不上传 cookie、待确认信封、数据库或完整提示词/代码。正向预览需实际 bundler/依赖网络，失败不能以假 ready 或截图补通过。

GEN-007 只落地本模块必要验收；GEN-008 再组合全套回归。默认 check、verify、CI 不调用真实模型；本地 UI 通过仍不替代 GEN-010 的两个真实需求或 GEN-009 的最终反代/地址验证。

## Risks / Trade-offs

- 创建 API 没有幂等键 → 只确认已取得的项目 ID，结果未知先看真实列表，不自动重发或猜测名称。
- 模型请求可能在用户离页后仍暂时在途 → 尽快取消连接并按服务端期限收尾，重开查询原请求，不宣称免除所有在途费用。
- 待确认需求暂存在当前标签存储 → 明确只是本地恢复辅助，按项目限额/过期，归属失败或新会话清理，不当作平台保存。
- 历史消息没有工具事件 → 保留真实对话和最新运行摘要，不补演；完整活动历史持久化不在此扩展。
- 多个组件争用取消/终态 → 单一请求控制器与身份检查，terminal 一次收口，查询与迟到响应不能覆盖新项目或已确认事实。
- 预览网络或模型权限不齐 → 保持错误和未验证状态；fixture 证明 UI/协议，真实调用与最终环境独立验收。

## Migration Plan

1. GEN-001～006 实际能力就绪后扩充共用公开 schema，兼容加入消息 backward 模式，完成 API/纯状态测试；不修改旧 change 的历史记录。
2. 接入会话/目录/项目客户端、单次创建命令和路由，迁移诊断页与原 smoke 入口，验证旧连接功能。
3. 接入有界 SSE 客户端、取消/查询和对话，随后组合 GEN-006 预览/采用及只读源码，完成对应浏览器场景。
