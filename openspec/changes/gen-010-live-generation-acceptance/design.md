# Design

## Context

动机见 [proposal.md](./proposal.md)。当前应用仍只有健康路由和连通性页面，package scripts 没有模型、发布或产品验收入口；下述命令均为计划能力。实际模型账户权限和密钥未验证，本次规划不读取密钥或调用 API。

[GEN-002](../gen-002-model-access-validation/design.md) 规划服务端 Responses 客户端与独立能力探针，[GEN-004](../gen-004-bounded-agent-generation/design.md) 规划六步以内生成和直接内核 live smoke；两者不验证可见工作台。[GEN-007](../gen-007-project-workspace/design.md) 规划 UI 路径，[GEN-008](../gen-008-integrated-regression/design.md) 汇总 fixture 回归，[GEN-009](../gen-009-local-release-validation/design.md) 验收独立产物和 Nginx。本任务消费这些实际实现，完成 [Top 1 的两个真实需求验收](../../../docs/product/core-paths.md#验收目标)，不重新实现产品内核。

## Goals / Non-Goals

**Goals:**

- 在已部署验收的相同发布字节上，从可见输入到真实生成、编译、交互、采用和重开取得完整证据。
- 用固定公开需求与确定结果评价质量，让失败可复现，调用和时间开销有界。
- 交付可现场演示的 Top 1 流程与明确的验证边界。

**Non-Goals:**

- 不新增产品接口、模板、模型适配、历史恢复、分享、自动修复、生成应用服务端或模型评判服务。
- 不以 live 验收替代既有负向/流/并发测试，不为重复测试错误路径额外付费。
- 不读取 ChatGPT/Codex 登录凭据，不将聊天订阅当成已可用 API 配置，不默认触发真实调用或操作公网服务器。

## Decisions

### 1 只验收明确选定的本地产物

新增 scripts/live-smoke.cjs 及根 `pnpm smoke:live`，完整执行必须同时提供 `--live --release <path> --deployment-report <path>`；无参数/--help 只显示说明，缺参数/非法参数非零且零模型调用。没有任意命令、任意 base URL、跳过用例、自动补跑或自动更换模型选项。

预检读取 release.json、实际文件摘要和 GEN-009 本次报告，要求完整部署必需用例/清理均通过且 releaseDigest 对应；只有源摘要相同不足以匹配。记录 live runner、公开用例和断言的独立 harnessDigest，防止用旧断言为新需求背书。缺报告、旧包被改、缺共享包/模板、平台/ABI 不匹配直接停止。

本次环境在 `test-results/live-generation/<runId>/{releases,shared,private,export}/`，复用 GEN-009 的搬迁/渲染/所属进程辅助；原发布目录只读，原生产数据不参与。后端使用原样 `node dist/server.js`，Nginx 使用独立前缀，origin 固定 http://127.0.0.1:8080；后端 loopback 3001。持久数据仅为本次绝对 DATABASE_PATH，没有 Vite、tsx、受控上游或应用构造注入。

精简子进程环境只显式传递必需系统值和 GEN-002 模型配置，保留 HOME 含义，清除 NODE_PATH/NODE_OPTIONS/真实开发数据库/代理配置。密钥只从执行者已配置的进程环境取得，不能作为 CLI 参数、浏览器输入或报告字段；不复制开发者 .env、登录缓存或全局认证。预检只检查模型配置有效，不通过额外远程探针请求验证。

若本任务补充的后端观测改变了运行代码，先重跑工程检查、release:build 和匹配的 smoke:deployment，才能付费验收；不得向旧发布包临时补文件。常规 check/verify/CI 只运行无真实凭据的控制测试，不调用本命令。

### 2 两个独立项目验证同一个原模板

在新浏览器上下文中从首页选择 company-landing，以可见表单提交完整需求，各创建一个新项目/一个 requestId；第二例仍从该原模板 v0 起步，不从第一例候选继续。创建前后核对模板 id/version/digest 和基线不含目标新增交互，避免已有 fixture 或旧项目被当成新生成。

新增 scripts/live-cases.mjs 保存公开自然语言需求、caseVersion、期望数据和业务计算函数；它属于测试输入，不打入发布包。提示词只规定功能、公开样例、可访问名称和沿用模板视觉，不提供组件实现、预写代码或测试脚本。现有 GEN-004 quote/filter 的直接内核样例保持原用途，不嵌套调用，也不把其通过记录算作本次 UI live 通过。

| 用例 | 公开需求与可访问控件 | 必需业务断言 |
| --- | --- | --- |
| studio（主演示） | 设计工作室官网，保留模板服务/套餐/导航/FAQ；增加 label 为“项目类型”的 select（企业官网/品牌电商）、label 为“页面数量”的 number（1–20）、名为“预估报价”的结果区；新增案例区及“案例行业”选择（全部/零售/科技） | 官网基础价 2000 元、电商 5000 元，每页 300 元；官网 1 页=2300、4 页=3200，电商 4 页=6200；案例“山海商店”“星桥零售”为零售，“云帆科技”为科技，全部 3 项/零售 2 项/科技 1 项，切回全部恢复 |
| schedule（第二需求） | 使用相同企业模板呈现公开课介绍，增加 label 为“活动领域”的 select（全部/设计/产品）和“活动形式”的 select（全部/线上/线下），显示“活动数量”和“暂无活动”空状态 | “设计入门”“视觉实践”为设计/线上，“品牌分享”为设计/线下，“产品工作坊”为产品/线下；默认 4 项、设计 3 项、设计+线上 2 项、产品+线上 0 项且空状态、切回全部+全部 4 项 |

studio 用例还检查空值、0、21 或非整数页数不会显示 NaN/负值/仍可误解为有效的错误报价；允许原生约束或明确校验，不规定具体 CSS 或组件内部结构。schedule 检查两个筛选按 AND 组合，不只改变标签或返回固定数量。

需求写明控件有可访问标签、结果可被辅助技术读取、业务数据仅为浏览器内交互，不宣称发送咨询、支付或预约。断言使用固定业务容器/可访问名称及真实可见条目，不依赖模型选择的文件名、CSS 类、DOM 顺序或源码字符串出现。未满足需求的可访问名称也是失败，不在事后修改 oracle 迁就结果。

### 3 调用计划与产品上限保持一致

一轮完整验收最多计划两个新生成请求，每例一次；GEN-004 每轮最多六次模型请求，因此计划最多十二次供应商请求。沿用 maxRetries=0、GEN-002 的配置值/默认值和 GEN-004 的步骤、256KiB 上下文、文件/工具限制，不为验收静默加大配置或自动修复。MODEL_ID 使用执行者明确配置的已选模型，不在 runner 内硬编码备用模型。

预检显示模型标识、两个用例、最大请求数、当前 MODEL_TIMEOUT_MS/MODEL_MAX_OUTPUT_TOKENS 和报告路径，不输出密钥；仅 `--live` 才能进入生成阶段。每轮输出上限传到每次真实请求，总上限按 2×6×实际配置输出上限记录；这是运行边界，不是人民币/美元账单封顶。按供应商返回用量记录，不估算未经核对的费用。[官方 token 说明](https://developers.openai.com/api/docs/guides/token-counting)指出输出计数包含不可见生成 token，因此不从生成代码长度推导用量。

第一例失败/阻塞/结果未知时停止第二例并记 not-run；不自动调用 GEN-002 all 探针或 GEN-004 live smoke。未预期的重复 generation/requestId 或额外模型调用属于验收失败，立即取消本次在途任务并停止所属服务，不接受偶然得到的正确结果。计划边界不构成供应商硬扣费承诺，取消/网络超时也不保证未计费。

生成状态不确定时只使用原 requestId 查询确认，不重新 POST；超过 GEN-007 的查询期限仍未知就失败退出。刷新、切换宽度、查看源码、采用、重开和后端停启都必须零新增模型调用。预览编译失败不能直接提交“修一下”让模型再次生成，也不手工修补本次候选；先保留失败证据，再将缺陷交回拥有该规则的 GEN 实现。

### 4 最小调用元数据证明真实来源

优先复用 GEN-002/004 已有安全观察能力。若不足，仅在该模型传输/生成调用边界补充两类结构化事实：真实传输发起，以及 SDK 步骤结束。按 runId/step/独立 requestAttemptId 关联，记录配置模型、可获得的实际响应模型、HTTP 状态、安全错误分类、耗时、供应商请求标识和用量；缺失字段记 null。产品项目/run/requestId 与供应商 request ID 不混用。

传输观察只包裹生产真实 fetch 并原样转发请求、signal 与响应，不替换响应、不添加额外请求、不读取/打印 body，不消费响应流；步骤完成后的 usage 从已固定 SDK 的元数据取得。网络发起与供应商确认收到分开记录，发送超时且无响应标识不能写成供应商已成功处理。[OpenAI 官方请求追踪说明](https://developers.openai.com/api/reference/overview#debugging-requests)支持保存 x-request-id 供排查，但它不证明编译或业务正确。

日志仅输出允许字段，拒绝原始 headers、URL 查询、prompt、tool arguments/results、代码、异常 cause、推理内容和认证值；标识/字符串有长度与可打印字符限制。观察器只记录安全事实，不影响业务状态、重试或截止时间，不新增数据库迁移、HTTP 字段或诊断接口。不引入通用 tracing/计费平台。

runner 收集所属生产后端日志到 private，按具体允许事件提取本次 run 的元数据；报告显示 dispatched 请求次数、收到响应的次数和 SDK 完成次数，不将不同指标相加成“总请求数”。用量缺失时总量记 null，可另给明确标注的已知部分合计；不以零代替未知。source=live 只在真实传输已经发起时成立；预检失败 source=not-run，控制测试 source=fixture。

### 5 自动化验证跨过每个实际边界

复用 GEN-007 的具体工作台交互和 GEN-009 的生命周期，新增用例业务 oracle；不能调用模型内核绕过 UI、预种候选、替换 iframe 页面、伪造 Sandpack ready 或修改模板让目标功能预先存在。

| 阶段 | 每例实际验证 |
| --- | --- |
| 基线与提交 | 记录原模板当前版本/digest；通过 UI 创建项目、提交一次；持久消息/run/requestId 与所见需求关联，活动对应真实工具 |
| 候选保存 | run=succeeded 且候选存在，候选 parent 为原 v0，文件/digest 有业务变化，entry/dependencies/来源固定，当前版本仍为 v0 |
| 编译与交互 | 真实隔离 iframe 编译成功，执行该例的计算或组合筛选断言；浏览器无未捕获错误，原导航/FAQ 等基线操作仍工作 |
| 源码检查 | 只读代码视图与同一候选返回的文件一致，文本转义且无执行；检查实际变化文件，不以代码关键词作为交互通过依据 |
| 采用 | 在控件验证成功后显式点击采用；API 返回/重查 current 为候选，未因 generated succeeded 自动采用 |
| 重开与隔离 | 刷新、离开项目再打开，候选已成为当前；文件/digest 和消息记录相同；另一空白浏览器无法读取私有项目 |
| 生产重启 | 同一 DB/cookie 下停止再启动所属原生产入口，两例均恢复相同 current/digest；重做关键交互，确认没有新模型请求 |

主案例和第二例都在 1366px 桌面与 320/375px 窄屏检查宿主及真实 iframe 无横向溢出、控件可操作；通过已有响应式容器调整并记录 iframe 实测宽度，不能只截取外层页面，也不为验收增加产品设备控件。复用已采用快照检查多宽度，不为每个宽度生成一次。

保留真实当前版本与未采用候选的区分。模型/编译/业务任何阶段失败都不能强行采用；当前仍为 v0 是正确的失败保护，不能把它记为需求完成。迟到/未知结果只查询确认，沿用已有产品状态语义。

### 6 自动化通过与可演示质量分别确认

产物与数据通过不代表视觉已复核。自动化报告含 automation.status、visualReview.status、acceptance.status；自动化成功时 CLI 可按自身范围退出 0，但必须输出“自动化通过，视觉复核待完成”，visualReview/acceptance 仍为 not-run，不能生成最终 Top 1 已通过结论。

实施者使用仓库 Playwright skill 查看运行页面与实际截图，逐例记录桌面、320/375px 观察和证据：沿用模板视觉/页面层次，新增区块可发现且样式完整，无重叠、裁切、不可读文字，控件/错误反馈清楚，原主要内容与 FAQ/导航保留。记录到本次 private/manual-review.json，绑定 releaseDigest/harnessDigest/caseVersion、观察代码及证据路径；只合并有实际观察的结果，不使用另一模型评分或自动给“美观”打分。

自动化结束前将必要作者 storageState 和实际截图保存到 private 后正常清理。复核按 GEN-009 已文档化的所属进程起停方式，以原包、本次 DB 和私有会话重开已有成果；此时不注入模型密钥，仅检查已保存快照，零新增生成。复核结束同样记录所属进程清理结果，不为查看页面重复运行 smoke:live。

复用报告辅助校验并合并该复核记录；缺项或失败不进入最终验收通过。只有两个真实用例的生成、自动业务/持久化、视觉复核、调用边界和清理全部通过，acceptance 才能 passed。单次通过只证明本轮两个公开需求，不推断任意需求的成功率、稳定性或生产 SLA。

### 7 失败、证据与时间预算

沿用 GEN-008 的 passed/failed/blocked/cancelled/not-run 与原子报告/脱敏导出：缺配置/产物/Chrome/Nginx 是 blocked 且未调用；认证/账户模型权限/额度等按 GEN-002 安全分类说明，不能改为 fixture 通过；模型拒绝、截断、工具/编译/业务失败、普通超时或报告矛盾是 failed。原因不明的网络失败不推测成纯环境问题，后续用例为 EARLIER_FAILURE。

报告包含 runId、releaseDigest/harnessDigest、模型配置非秘密摘要、模板来源、用例版本、项目/run/版本关联、修改路径/摘要、各阶段观察、实际请求/用量/耗时与清理。provider IDs、完整日志、数据库、cookie/storageState、源码及截图原图保留 private；export 只放允许的安全摘要和确认遮罩后的截图，不上传 HAR、trace、真实密钥或原始错误。日志与 report 的敏感哨兵控制测试是默认检查的一部分。

复用 GEN-009 同一部署验收互斥锁，避免在 8080/3001 上并跑；有未知占用立即阻塞。总预算初始 10 分钟，单次生成不超过已配置 60s 默认/120s 最大，首部/状态查询/预览沿用已有边界，清理 10s。SIGINT/SIGTERM 停止新用例、结束在途请求并只清理所属浏览器/Node/Nginx；未完成清理仍非零。SQLite 与私有诊断保留，不自动删除演示数据或接管外部服务。

CLI 0 仅表示自动化必需检查与清理通过，1 为断言/输出/清理失败，2 为缺前置，130/143 为中断；整体验收同时要求第 6 节的实际复核。代码/模型配置/用例变化后，新证据使用新 runId，不覆盖历史失败。修复影响发布字节时重新构建并跑 GEN-009，再按本次明确 live 范围验证，不把旧截图接到新包上。

### 8 演示指引只描述已经核验的范围

新增 docs/product/demo-guide.md 并接入 docs 索引，README 链接最短入口，Verification 维护命令与覆盖，Lifecycle 只补必要的本次数据/会话重开操作。指引给出 3–5 分钟顺序：展示原模板 → 在工作台输入 studio 需求 → 查看实际工具活动与候选文件 → 操作报价/案例筛选 → 明确采用 → 刷新重开；第二例展示不同的组合筛选和空状态。

现场新生成需真实调用且可能失败/消耗额度；时间有限可打开已保存的真实成果并说明验证日期/用例，不能把预录过程、已有项目或静态截图说成刚刚生成。已有成果重开必须保留作者 cookie；私有 storageState 只供本机复核，不发布会话令牌或以新浏览器绕过归属。数据保留是平台快照，不承诺 iframe 内临时输入随刷新保存。

仅在实际最终验收通过后更新 core-paths 中 Top 1 的验证范围/日期；Top 2 历史恢复、Top 3 分享、公网服务器/TLS 与 hosted CI 继续分别记录未运行。GEN-010 不因为十个提案齐全就宣称十项实现完成，也不生成新的平行任务清单。

## Risks / Trade-offs

- 真实模型生成质量存在波动 → 固定公开需求/业务 oracle、每例只跑一次并保留失败，不事后手写候选或删掉失败记录。
- 账户权限或配置仍未准备好 → 预检/实际请求诚实报阻塞，API 可用性不由聊天套餐推断；本次规划不索要或检查密钥值。
- 额度与用量不等于已知账单 → 限制计划请求与输出、记录未知值，不宣称硬金额封顶或取消免费。
- 补充调用观测改变发布字节 → 先重建和复验 GEN-009；观测不得扩大产品 API 或读取响应正文。
- 外部 Sandpack 网络/窄屏质量未过 → 该用例仍未验收，不用假编译/单张截图代替实际操作和复核。
- 本地成功被扩展为全产品或公网成功 → 结论明确限定 Top 1、相同产物、两个需求及当前环境。

## Migration Plan

1. GEN-001～009 实际能力可用后固化两个公开用例与 oracle，并在无真实请求的控制测试中验证预算和失败规则。
2. 补齐必要安全调用元数据和发布报告检查，接入原样生产入口/Nginx 生命周期及 UI 业务断言；默认工程/CI 仍无 live。
