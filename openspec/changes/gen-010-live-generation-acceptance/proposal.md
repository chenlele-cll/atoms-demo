# Proposal

## Why

前面的受控 SDK 回归与本地部署验收能够检查工程链路，仍需证明真实模型能把所选模板改造成可操作的应用。`GEN-010` 用两个公开需求完成 Top 1 的真实浏览器验收，确认生成质量、业务交互、采用、持久化与演示准备，并将结论绑定到实际发布产物。

## What Changes

- 新增独立计划入口 `pnpm smoke:live --live --release <path> --deployment-report <path>`，消费 GEN-009 已通过的相同发布产物，在独立本地数据和 Nginx 实例上运行原生产入口；无参数/帮助不调用模型，不接入默认 check/verify/CI。
- 固定同一个 company-landing 模板的两个需求：主案例为设计工作室报价与案例筛选；第二例为活动日程的组合筛选与空状态。各自从原模板新建项目，通过可见工作台发起真实生成，不预种候选或替换成预写业务代码。
- 每例只发起一次生成，产品每轮至多六次模型请求，两例计划上限十二次；按用户 2026-10-18 修订取消默认任务总期限，保留输出和工具限制，无自动补跑、修复循环、模型切换或额外能力探针。
- 实际检查供应商调用/工具与快照关联、真实编译、确定性业务结果、只读源码、采用前后当前版本，以及刷新/生产后端重启后的同版本和同交互；复用 GEN-007～009 的具体辅助。
- 按需补充最小安全调用元数据，记录实际供应商/模型、请求数、用量、耗时和请求追踪，不向浏览器开放模型凭据、原始响应或推理内容，不新增诊断 API。
- 自动断言与桌面/窄屏视觉复核分别记录；单次 API 成功、生成状态 succeeded 或编译成功均不能代替整体验收。失败保留事实和原当前版本，未经模型调用的缺前置标 not-run/blocked。
- 形成可供面试演示的操作指引，明确新生成、已有真实成果与历史验证记录的区别；本任务收口 Top 1，不把尚未实现的历史恢复或分享写成已通过。
- 原规划阶段不运行模型；目前 GEN-001～009 已有实现和本地验收证据。用户针对实际 60 秒超时要求取消任务总期限，本次同步修改后端、前端和 live 验收等待；仍不操作公网服务器。

## Capabilities

### New Capabilities

无。本变更增加工程验收、有限安全观测及演示文档，不新增产品能力；使用 `skip_specs: true`，不创建产品 spec。

### Modified Capabilities

生成时长策略修订：MODEL_TIMEOUT_MS 默认为 0（无累计截止），正值仅为显式 opt-in；前端和 live 入口不再另设默认累计截止。保留取消、连接故障检测、步骤/token/文件限制和既有公开 HTTP 契约。GEN-002/004 旧规划中的 60 秒/120 秒限制由本次用户决策取代，历史失败记录不改写。

## Impact

- 根工程：live runner、固定公开用例/业务断言、无真实调用的控制测试；复用 Node 测试器、Chrome/playwright-core、所属进程和报告辅助，无新测试框架或模型评判服务。
- 后端：补充安全观测，并取消默认生成/模型共享累计截止，保留显式有限期限与取消；运行真实生产客户端，不注入 fixture、不改为 Codex 子进程或读取登录缓存。
- 发布衔接：若运行代码发生变化，重新生成产物并取得匹配的 GEN-009 部署通过报告；旧产物/旧报告不能为新代码背书。
- 文档：README/Verification 维护入口、前置与证据；新增 docs/product/demo-guide.md 维护演示顺序并接入 docs 索引，core-paths 只按实际验收更新 Top 1 状态。公网服务器/TLS、Top 2/3 与 hosted CI 保持独立状态。
