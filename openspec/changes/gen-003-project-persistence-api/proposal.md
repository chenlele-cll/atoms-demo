# Proposal

## Why

当前后端只有健康接口，项目、对话和代码没有持久化，也没有可用于重新打开项目的接口。`GEN-003` 建立项目数据与归属边界，让后续生成、预览和工作台可以依赖真实保存与恢复，而不把浏览器缓存当成平台持久化。

## What Changes

- 使用既定 SQLite 与 better-sqlite3 方案，保存匿名会话、项目、不可变代码快照、对话和生成记录；提供实际迁移、参数化查询、短事务和关闭连接行为。
- 从 `GEN-001` 的服务端可信模板文件集合创建项目，在同一事务中保存来源、完整初始快照和当前版本引用；浏览器只提交模板标识、版本、内容标识及项目标题。
- 提供匿名会话初始化、公开模板目录，以及当前会话的项目创建、分页列表、项目详情和分页对话查询接口。新项目对话为空、生成记录为空，不制造生成活动。
- 使用服务端会话 cookie 校验项目归属，对其他会话与不存在的项目统一返回不可访问结果；补充写请求来源检查、输入/响应运行时校验、请求频率和项目数量限制。
- 为后续生成提供内部的消息、候选快照和生成记录存储操作；本次不增加对应公开写接口，不调用模型、不采用候选版本或恢复历史。
- 验证真实数据库回滚、重新打开文件、HTTP 访问隔离、浏览器 cookie 与代理，以及本地构建产物重启后的恢复；测试使用隔离数据目录和明确的测试记录。
- 本轮只生成规划。实施依赖 `GEN-001` 的模板基线，不依赖 `GEN-002` 的 API 凭据；完整工作台、生成编排、事件流、版本采用及分享由后续任务承担。

## Capabilities

### New Capabilities

- `project-persistence`: 在匿名会话归属下创建、保存和读取平台项目及其代码、对话和生成记录，保证初始快照、事务一致性、访问隔离和重启后恢复。

### Modified Capabilities

无。当前没有已有的长期产品规格；GEN-001 的独立模板基线入口与现有健康接口继续保留。

## Impact

- 后端：项目契约、模板目录加载、SQLite 存储和迁移、会话与项目路由、配置及生命周期接入；不把这些逻辑全部放入路由或监听入口。
- 公开 HTTP：新增 `/api/session`、`/api/templates`、`/api/projects`、`/api/projects/:projectId` 和项目对话查询；采用单一权威 schema，不让浏览器导入后端实现。
- 模板准备：扩展 GEN-001 的准备与打包，后端使用中立模板源的独立部署副本，不读取前端实现或依赖前端 public 目录维持运行。
- 依赖：后端增加固定的 better-sqlite3、Zod、cookie 与限流插件及必要类型；native 构建仅准许实际依赖，仍共用唯一 lockfile，无 ORM、数据库容器或外部基础设施服务。
- 验证与说明：增加真实文件数据库、API、浏览器及构建产物恢复测试；更新隔离副本的必要资产/native 安装前提和 owning 文档。前端项目工作台与专用 HTTP 客户端在 GEN-007 接入。
