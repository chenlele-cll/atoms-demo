# Spec Delta

## Purpose

为模板生成平台提供具有匿名会话归属的项目保存与恢复能力，使后续生成、预览和工作台能够读取一致的代码、对话与生成记录，并在进程重启或请求失败后保持明确的数据状态。

## ADDED Requirements

### Requirement: 可持续使用的匿名项目会话

系统 SHALL 通过 `POST /api/session` 初始化或复用匿名会话，以 HttpOnly、SameSite=Strict、Path=/api 的 cookie 标识归属；公网 HTTPS 使用 Secure。会话有效期为 30 天，持久层 MUST 不保存原始 bearer token，响应体 MUST 不暴露 token 或其摘要。

#### Scenario: 创建会话并在重启后复用

- **WHEN** 浏览器以允许的来源提交空 JSON 对象初始化会话，并在后端重启后携带未过期 cookie 再次初始化
- **THEN** 首次请求返回 201 并设置 cookie，后续请求返回 200，且继续访问同一归属下的项目

#### Scenario: 无效会话不能认领原项目

- **WHEN** cookie 丢失、无效或对应会话已过期
- **THEN** 私有项目接口返回 401；重新初始化产生独立会话，不能认领旧会话的项目

### Requirement: 从可信模板原子创建项目

系统 SHALL 公开 `GET /api/templates` 元数据目录，并接受有效会话提交 `templateId`、`templateVersion`、`templateDigest` 与标题创建项目。系统 MUST 从服务端校验过的模板保存完整初始快照、来源和当前版本引用，全部成功才返回 201；初始版本为模板版本，消息列表为空且无生成记录。

#### Scenario: 创建可重新读取的模板项目

- **WHEN** 用户从目录选择 GEN-001 的有效模板并提交标题
- **THEN** `POST /api/projects` 返回项目详情与完整初始代码快照，当前版本指向该快照，后续读取具有相同文件内容、入口、依赖和模板来源

#### Scenario: 模板已变化或客户端注入代码

- **WHEN** 模板不存在、目录版本或内容摘要已变化，或者创建请求携带代码文件、所有者或当前版本等额外字段
- **THEN** 不存在返回 404，版本或摘要冲突返回 409，非法字段返回 400；均不留下项目或初始快照

#### Scenario: 模板源更新不改变已保存项目

- **WHEN** 项目创建完成后，原模板目录被更新或移除
- **THEN** 已保存项目仍从持久层返回创建时的完整快照，不从当前模板重建内容

### Requirement: 按会话隔离项目读取

系统 SHALL 提供当前会话的分页项目列表、项目详情和项目对话读取接口。所有私有查询 MUST 在服务端校验有效会话与项目归属；列表不包含其他会话的项目，其他会话的项目和不存在的项目返回相同形状的 404。公开目录和健康请求 MUST 不隐式创建会话。

#### Scenario: 两个会话访问同一个项目

- **WHEN** 会话 A 创建项目后，会话 B 请求其列表、详情或对话
- **THEN** B 的列表不包含该项目，详情与对话均返回 404；A 能继续读取

#### Scenario: 项目列表分页有确定顺序

- **WHEN** 有效会话使用合法 `limit` 和游标读取项目列表
- **THEN** 返回按更新时间与项目 ID 确定排序的元数据及下一页游标，单页最多 50 条，不在列表内返回完整代码

### Requirement: 可恢复的对话与生成记录

项目详情 SHALL 返回当前版本快照和最新生成记录摘要或 null；对话接口 SHALL 按项目消息序号升序分页。持久层 MUST 为后续编排提供保存消息、生成记录和候选快照的内部能力，不通过本次公开接口伪造生成活动；候选快照保存后 MUST 不改变当前版本。

#### Scenario: 明确测试记录在重新打开后保持一致

- **WHEN** 内部调用保存标记为测试夹具的消息、生成记录及候选快照，关闭后重新打开同一数据文件
- **THEN** 项目详情和对话返回相同记录与顺序，当前版本仍为保存候选前的版本，记录中的关联均属于同一项目

#### Scenario: 对话分批读取

- **WHEN** 所有者以 `afterSequence` 和最大 50 条的 `limit` 查询项目对话
- **THEN** 仅返回该序号之后的有序消息和下一批起点；没有消息时返回空列表与空的下一批起点

### Requirement: 不可变快照与事务一致性

已保存的代码快照 MUST 不可原地覆盖；项目当前版本、父版本、消息和生成记录的关联 MUST 不跨项目。一次逻辑写入涉及的记录 SHALL 全部提交或全部回滚；写入失败 MUST 不返回保存成功，也不得留下部分项目、孤立快照或失配的关联。

#### Scenario: 初始保存中断

- **WHEN** 创建项目时在插入初始快照或设置当前版本过程中出现写入错误
- **THEN** 整次创建回滚，列表和详情不能读到半成品；后续有效请求仍可正常保存

#### Scenario: 关联或快照内容无效

- **WHEN** 内部写入尝试覆盖已有快照、引用其他项目的版本，或保存不符合文件安全约束的内容
- **THEN** 操作被拒绝，已有记录和当前版本不变

### Requirement: 输入输出具有运行时契约

系统 MUST 在运行时校验请求路径、查询、请求体、模板内容与公开响应，并使用显式 DTO 排除内部字段。标题修剪后为 1–120 字符，分页 `limit` 为 1–50，游标及序号有界；完整代码快照遵守 GEN-001 的路径、64 文件及 2 MiB 限制。非法输入 SHALL 返回 400，不通过类型断言直接进入查询。

#### Scenario: 非法请求不进入有效存储路径

- **WHEN** 请求携带非法项目 ID、超长标题、负序号、损坏游标、额外字段或越界分页参数
- **THEN** 返回稳定的 400 错误，不产生或修改记录

#### Scenario: 存储内容损坏

- **WHEN** 读取到无法通过快照契约校验的持久化内容
- **THEN** 返回安全的服务错误，不把原始记录发送给浏览器，也不以当前模板静默替换历史内容

### Requirement: 写入来源与资源边界

所有公开 POST 请求 MUST 为 JSON 且来自配置的精确 Origin 白名单；缺失或不允许的 Origin 返回 403。系统 SHALL 限制会话初始化及项目创建频率、创建请求体大小和每会话项目数；达到频率上限返回带 Retry-After 的 429，达到项目数上限返回 409，失败不得产生部分写入。

#### Scenario: 跨来源写入被拒绝

- **WHEN** 请求携带有效 cookie，但 Origin 缺失或不在白名单内
- **THEN** 会话初始化或项目创建返回 403，不设置新会话，也不创建项目

#### Scenario: 连续请求和项目配额

- **WHEN** 客户端超过配置的每分钟频率或会话项目总数上限
- **THEN** 分别返回 429 或 409，已有项目仍可读取；伪造转发 IP 头不能绕过单客户端频率限制

### Requirement: 安全错误与敏感信息最小化

公开错误 SHALL 统一为 `{error:{code,message},requestId}`，私有响应 SHALL 使用 `Cache-Control: no-store`。错误响应和日志 MUST 不包含会话凭据、凭据摘要、SQL、绑定值、绝对存储路径、提示词或完整代码；正常响应仅通过受控 cookie 设置会话凭据，项目内容仅向所有者返回。数据库不可写等临时故障返回安全的 503。

#### Scenario: 写入失败可定位且不泄密

- **WHEN** 数据库忙、磁盘写入失败或其他存储异常使请求无法完成
- **THEN** 响应包含稳定错误码和请求 ID，日志仅记录必要分类与请求 ID，不声明保存成功、不返回底层 SQL 或敏感测试哨兵值

### Requirement: 文件持久化与生命周期失败可见

正式启动 SHALL 使用显式配置的数据文件并在监听前完成存储初始化；重启后恢复项目、会话、快照、消息与生成记录。非法配置、不可读写文件或不支持的数据库版本 MUST 使启动失败，不回退到内存或清空已有数据；正常关闭和启动失败 SHALL 释放所拥有的存储资源。

#### Scenario: 构建产物重启恢复

- **WHEN** 使用本地构建产物创建项目，停止后端，再以相同数据文件重新启动
- **THEN** 原浏览器会话能够读回项目、完整代码和已存记录，内容摘要一致，恢复过程不依赖前端源文件

#### Scenario: 不兼容数据文件

- **WHEN** 启动配置无效或数据文件声明了当前程序不支持的更高版本
- **THEN** 后端在监听前失败并报告安全原因，不执行破坏性迁移，不覆盖或删除该文件
