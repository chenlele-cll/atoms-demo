# Design

## Context

动机和功能范围见 [proposal.md](./proposal.md)，行为契约见 [template-baseline](./specs/template-baseline/spec.md)。当前 `frontend/src/App.tsx` 只有手动连接检查，`scripts/smoke.cjs` 已验证该按钮、异常响应、后端离线、窄屏和构建产物；后端只有健康接口。本变更保留这些行为。

已读取上游固定提交的入口、FAQ、价格、导航、主题和订阅组件。该模板使用 React 18、TypeScript、Tailwind 3 及本地 shadcn/Radix 组件，页面通过静态组件组合，具备现成 FAQ、主题和手机菜单。需要适配的问题包括 `@/` 路径、图片导入与远程头像、Tailwind 构建、全局 `vite-ui-theme` 存储键，以及未绑定真实行为的套餐按钮和仅打印 `Subscribed!` 的订阅表单。

宿主使用 React 19、TypeScript 和 CSS Modules，当前没有模板或 Sandpack 依赖。模板可以维护自己的 React 版本与样式，不要求升级上游组件或改变平台设计。

## Goals / Non-Goals

**Goals:**

- 引入一个可阅读、来源固定的官网模板，用独立文件集合运行，并保留未来项目快照可复用的元数据。
- 解决模板资源与浏览器预览的实际接入问题，交付可以独立打开及自动回归的基线页。
- 将已有组件的适配限定在启动、资源、路径、反馈与隔离，不重新制作官网。

**Non-Goals:**

- 不添加项目 API、数据库、模型供应商、生成工具、任务流、候选版本采用或完整工作台。
- 不实现报价估算器等未来由模型生成的业务增量，也不引入第二个场景模板。
- 不实现自托管 bundler、独立站部署、远程服务器操作或新的通用模板框架；本地构建产物验证不等于完整 Top 1 验收。

## Decisions

### 1 固定上游组件作为模板资产

选择仓库 `leoMirandaa/shadcn-landing-page`，固定提交 `ae3716dbce5c8a26815222bb743994b5717938f1`，本地模板标识 `company-landing`、版本 `1`。使用该提交的源码与 MIT 许可，不在运行时拉取远端分支。

计划在 `templates/company-landing/` 保存适配后的 `src/`、必要资源、`LICENSE`、`manifest.json`、样式配置和 `ADAPTATIONS.md`。清单记录来源提交、选取文件、上游原始校验值、直接运行依赖的精确版本、入口和模板版本；适配说明区分原有能力与本地改动。保留现成页面骨架，未使用的开发工具、部署脚本、锁文件和缓存不引入。

该目录是公开模板源资产，不是新 workspace 应用，也不是可供执行模型命令的目录。后续后端可以读取中立的资产格式，不需要导入前端 UI 源码。相较把组件直接合进宿主，这种组织能保持模板运行边界及来源清楚；相较额外维护完整上游应用，减少第二套安装与起停流程。

### 2 提前编译样式并准备自包含文件集合

计划新增 `scripts/prepare-company-template.mjs`，只读取固定本地文件，编译上游样式，生成稳定排序的虚拟文件映射。适配后的组件使用明确的相对导入；所需 PNG/SVG 资源打包为可被虚拟模块使用的内嵌资源，远程头像改用本地资源或无外部请求的占位显示。

Tailwind 3、PostCSS、Autoprefixer 和 `tailwindcss-animate` 只作为模板准备的开发依赖，锁入根 lockfile；初始兼容版本沿用上游清单对应版本，安装时核对实际可用性。模板的 React 固定为 `18.3.1`，其余实际使用的运行依赖从固定提交的清单和安装元数据确定精确值。它们写入模板运行清单，不安装进宿主 UI。

普通开发和构建需要在 Vite 启动前完成准备。将准备入口接到前端实际 `dev` 和 `build` 脚本，使已有独立命令、manager 及 `pnpm smoke` 自然复用，不新增进程管理分支。已存在的准备输出使用原子替换；失败不继续启动或构建出缺资源的页面。

输出为前端公开静态资产 `frontend/public/template-assets/company-landing.bundle.json`，由 Vite 构建复制进 `dist/`。该文件是可重建的产物，加入忽略规则；固定源文件与许可进入版本控制。内容标识由稳定的文件和元数据计算，不写入每次构建变化的时间戳。准备测试使用隔离临时目录。

选择提前编译而不是运行时 Tailwind CDN，是为了保留上游主题配置并减少浏览器网络依赖。预编译只覆盖当前模板基线；后续 `GEN-004` 增加样式时可修改普通 CSS，任意新 Tailwind 类不会因基线 CSS 存在而自动生效，不能把这项能力留成隐含假设。

### 3 单个公开资源格式及最小加载器

文件集合包含 `id`、`version`、`name`、`category`、`source`、`entry`、`dependencies`、`files` 和 `digest`。`files` 为虚拟路径到源码文本的映射，包含所需入口和已编译 CSS；不包含 `.env`、服务器配置或任何秘密。`digest` 用于确定构建内容，不能当作对不可信代码的安全认证。

计划在 `frontend/src/templates/companyLanding.ts` 实现公开资产加载及运行时解析，显式处理 HTTP 失败、JSON 解析、标识与版本不匹配、非法路径、缺失入口和超限。初始限制为至多 64 个虚拟文件、总正文不超过 2 MiB；只接受当前模板使用的固定直接依赖和正常化的绝对虚拟路径，拒绝 `..`、非规范路径与宿主路径。

资源由前端静态托管，属于模板文件资产，不增加 `/api` 契约。后续 `GEN-003` 可在自己的提案中把模板元数据及文件集合接入项目创建。当前不为一个静态模板预建共享运行时包、服务层或动态目录 API。

### 4 保留首页并增加独立基线页

计划新增 `frontend/src/template-baseline/TemplateBaseline.tsx`、对应 CSS Module 和最小预览组件。在 `App.tsx` 中为 `/templates/company-landing` 提供页面分支，首页增加进入链接；普通链接和重新加载足以服务这一个入口，不新增路由库。

基线页显示模板名称、版本、来源、“模板原版”状态、预览及失败重试。预览和源码按文件集合运行，不把上游组件导入宿主 React 树。宿主沿用现有设计契约，不新增模型输入、生成按钮、项目列表或未实现的工具栏。

前端添加固定版本 `@codesandbox/sandpack-react`，优先验证已核对 peer 范围的 `2.20.0`。使用隔离 iframe 加载模板自己的 React 18 与运行依赖，固定入口及文件集合，不向预览传递宿主 cookie、配置或模型凭据。客户端 props 和 UI 只读设置不作为未来模型文件权限的安全边界。

### 5 从实际预览结果更新状态

加载器状态与预览状态分开处理。页面从资源加载进入编译等待，仅在对应预览实例收到实际初始化编译结果且未报告错误时显示可运行；iframe 的 `load` 事件或经过固定时间不构成成功依据。

资源失败、编译错误与初始化超时都提供明确反馈。初始预览截止时间设为 60 秒，可在实际接入测量后调整；超时后继续保持失败状态，用户主动重试才建立新的预览实例。每轮请求带取消控制，卸载和重试时结束旧请求及监听，忽略旧实例晚到的回调。

预览长内容在框架内滚动；布局测试同时检查宿主文档和 iframe 文档的实际宽度。iframe 具有描述性标题，宿主提供可见错误和键盘可达的重试入口。

### 6 仅修正影响基线可信度的上游行为

保留导航、FAQ、明暗主题及手机菜单，补充缺失的可访问名称和必要焦点行为。把套餐与 CTA 的空动作改为有明确文案的真实页面内导航；处理无目标的联系入口。删除 Newsletter 表单及相关入口，避免把打印日志当成订阅能力，也避免引入额外收集信息的后端。

主题状态采用该预览实例内存，不沿用通用 localStorage 键；主题只作用于预览 document。示例团队、价格和文案保留模板演示身份，必要时替换为明确的样例内容，不冒充真实业务或已完成 AI 生成。适配代码保持严格类型，不保留上游 `any` 作为项目新逻辑的逃生口。

### 7 每层采用现有工具验证

模板准备使用 Node 内置测试器，新增 `scripts/prepare-company-template.test.mjs`，验证固定输入重复输出、缺文件或许可失败、非法路径、超限及不完整输出保护。测试针对包边界与失败行为，不断言每段静态文案。

浏览器回归新增 `scripts/template-smoke.cjs`，继续使用已有 `playwright-core` 与系统 Chrome，不增加测试框架。计划新增 `pnpm prepare:template`、`pnpm test:template` 和 `pnpm smoke:template`；这些命令目前不存在，实施时加入并更新文档。`smoke:template` 要求先完成 `pnpm build`，自行启动和清理所属前端 dev、preview 进程，使用端口 5173/4173，端口被占用时失败且不结束其他进程。

自动化验收矩阵：

| 场景 | 操作与断言 |
| --- | --- |
| 桌面真实预览 | 新浏览器上下文直接访问基线页，等待实际就绪；在 iframe 内验证价格导航、FAQ 展开和收起、主题切换；宿主主题不变 |
| 手机与键盘 | 320/375px 以及 1280px，检查宿主与预览无横向溢出；手机菜单打开、选择目标后关闭；键盘操作与焦点恢复有效 |
| 静态资源失败 | 浏览器请求拦截将模板资源变为 404、非法 JSON 或结构无效，断言对应错误；恢复响应并重试成功 |
| 真实编译失败 | 返回结构合法、内容标识相符但入口包含语法错误的文件集合，让实际预览编译失败，断言没有可运行状态；恢复正常资源后重试 |
| 预览服务不可达 | 使用新上下文阻断实际 bundler 请求，检查截止时间与错误状态；解除阻断后主动重试 |
| 构建产物 | 对 `frontend preview` 重跑主要交互和窄屏检查；资源来自 `dist/`，不依赖上游开发服务器；刷新与直接访问有效 |
| 既有功能回归 | `pnpm smoke` 继续检查健康请求、非法响应、后端离线、窄屏与构建产物连通性 |

成功场景同时采集宿主与 frame 的未捕获异常，预期故障场景单独分类，不能用截图命令成功替代交互断言。输出位于忽略的 `test-results/template-baseline/`；手工浏览器检查按仓库 Playwright skill 使用独立会话。

## Risks / Trade-offs

- 外部 bundler 与依赖网络仍可能不可用 → 在实现前半段做真实浏览器接入，明确超时和错误；不能报告离线运行已保证，也不在本任务扩展为自托管服务。
- 上游 Tailwind、资源与别名造成样式缺失 → 固定本地准备流程，保留上游配置和必要资源；浏览器检查真实计算样式及交互，避免只看到结构就通过。
- 模板体积或依赖导致适配投入超出小任务 → 优先移除不影响官网基线的演示区块并记录原因；如仍无法保留主要交互，则报告具体原因并修订本提案，不自动引入其他场景或重写模板。
- 第三方 TSX 被当成宿主代码检查 → 模板源码作为独立资产，必要时在 lint 中明确排除该资产目录；宿主和准备逻辑继续严格检查。预览运行验证不能被该排除替代。
- 缓存或旧回调造成误报成功 → 新实例识别、固定内容标识、新浏览器上下文及故障后重试检查共同覆盖。
- 与并行中的工具配置任务发生冲突 → 只修改本功能需要的脚本和配置片段，保留 manager、基础设施、现有 Git 状态及其他 change。

## Migration Plan

1. 引入固定源文件、许可和适配记录，加入实际需要的准备及前端依赖，更新唯一 lockfile。
2. 完成模板准备与单元边界测试，再连接基线页；首页原有连接检查继续工作。
3. 运行 frozen install、工程检查、准备测试、原有 smoke 和模板专用 smoke；记录实际退出结果与浏览器观察。
4. 在 `README.md`、产品来源记录、Monorepo 及 Verification 文档中更新本次已实现能力和使用前提，不把后续 `GEN` 能力写成已完成。
5. 如需回退，仅移除本变更的模板资产、入口、准备和依赖变更；本任务没有数据库或用户数据迁移。源文件格式、固定依赖、准备方式与实际验证结果交接给后续子任务。
