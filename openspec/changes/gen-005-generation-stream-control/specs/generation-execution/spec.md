# Spec Delta

## Purpose

让项目所有者能够通过受保护的任务事件流观察和控制生成，并在重复提交、取消、连接中断或服务重启后查询明确的持久化结果，同时限制并发与资源使用，保留原有当前版本。

## ADDED Requirements

### Requirement: 公开生成接口验证归属与契约

系统 SHALL 提供项目生成 POST、按请求标识查询状态和取消接口，复用有效匿名会话与归属校验；所有 POST 必须通过 JSON、Origin 和运行时契约检查。生成仅接受 requestId、baseVersionId 和 prompt，不能由客户端改变模型、工具、预算或代码。开流前拒绝 MUST 使用安全 JSON 错误且不调用模型。

#### Scenario: 非所有者不能观察或控制任务

- **WHEN** 会话 B 请求会话 A 项目的生成、状态或取消接口
- **THEN** 返回与不存在资源相同形状的 404，不泄露运行标识或活动，不影响 A 的任务；无有效会话返回 401

#### Scenario: 请求无效或未配置模型

- **WHEN** 生成请求包含非法字段、超限需求、不允许的 Origin、过期基线或缺少模型配置
- **THEN** 在开流和供应商调用前返回对应 JSON 错误，不创建运行或用户消息

### Requirement: 受理后通过同一 POST 发送任务事件

新的合法生成 SHALL 以 `text/event-stream` 返回 accepted、activity 和 terminal 事件，第一帧确认已持久化受理，后续活动只对应实际工作。业务事件具有递增序号及项目/请求/运行关联；心跳不算进度。成功终态 MUST 对应已提交候选且注明预览未验证，EOF 或 HTTP 200 本身不构成成功。

#### Scenario: 模型完成前收到受理帧

- **WHEN** 新请求已受理但受控上游仍在等待
- **THEN** 客户端能先读到 accepted，随后按序读到真实活动与至多一个 terminal，不需要等待整个生成完成才收到首帧

#### Scenario: 开流后生成或存储失败

- **WHEN** 响应头已发送后模型失败或终态存储失败
- **THEN** 可写连接收到分类失败终态；若持久化未确认则明确 unknown 和未确认标记，不把 JSON 错误混入 SSE，也不发送成功终态

### Requirement: 重复请求返回原状态而不重建流

相同项目、requestId、基线与需求的重复 POST SHALL 返回原运行的 JSON 状态：活动运行中为 202，已确认终态为 200；无执行者的未确认记录按未确认规则处理，不同载荷复用 requestId 返回 409。重复请求 MUST 不重新调用模型、追加消息或建立第二条活动流，也不能通过关闭重复请求连接中止原任务。状态查询不得触发模型调用。

#### Scenario: 同时重复提交相同请求

- **WHEN** 原请求运行时另一连接提交相同请求，随后关闭该重复连接
- **THEN** 重复请求只取得 202 JSON，原连接和运行继续，数据库只有一条受理记录及对应用户消息

#### Scenario: 已结束请求或载荷冲突

- **WHEN** 调用方重试已结束的相同请求，或改变需求复用原请求标识
- **THEN** 前者返回原终态及已保存候选标识，后者返回 409；均不增加模型请求

### Requirement: 取消操作幂等且不谎报完成

所有者取消活动任务 SHALL 立即传播中止信号，并在尚未确认终态时返回 202 和 cancellationRequested=true；重复取消保持幂等。已结束任务返回 200 原终态；取消在成功提交前生效 MUST 阻止候选保存，成功先提交则保持成功。准入槽位在执行清理完成后才释放。

#### Scenario: 活动任务被多次取消

- **WHEN** 所有者在模型等待中连续请求取消
- **THEN** 请求不会启动其他任务，活动上游被中止；最终查询为 cancelled 且无候选，原需求与当前版本保留

#### Scenario: 保存与取消发生竞争

- **WHEN** 取消与成功保存接近同时发生
- **THEN** 只产生一个一致终态：取消先于提交则不保存候选，提交先完成则返回 succeeded，不能同时报告成功和取消

### Requirement: 断线终止未完成生成并允许查询确认

生成响应连接在正常终态之前关闭 SHALL 中止未完成生成，不承诺后台续跑。客户端可凭预先生成的 requestId 查询已受理运行；失去终态时 MUST 不将 EOF 当成完成，也不自动重发生成。活动事件不持久重放，重连只查询状态；已成功提交的候选不因断线删除。

#### Scenario: 浏览器提前结束读取

- **WHEN** 原始流在模型请求等待中被客户端中止，且后端观察到响应连接关闭
- **THEN** 活动请求被中止、后续模型步骤停止；查询最终为 cancelled 并标明断线原因，不产生候选

#### Scenario: 成功后丢失末帧

- **WHEN** 候选已提交但客户端未收到 terminal 即失去连接
- **THEN** 状态查询返回已存 succeeded 和候选标识，不重复调用模型，也不把该结果改为取消

### Requirement: 生成准入与调用规模受限

系统 SHALL 默认限制每项目 1 个、每会话 1 个、全局 2 个活动生成，并限制生成 POST 每 IP 每分钟 6 次、每会话滚动 24 小时最多 20 次新受理。超限不排队，不创建新运行或调用模型；项目冲突返回 409，会话/频率/日配额返回 429，全局满载返回 503。重复受理不重复扣日配额。

#### Scenario: 不同请求争用同一项目或会话

- **WHEN** 新请求与现有运行争用项目或会话活动名额
- **THEN** 返回对应 409 或 429，不增加运行、消息和上游请求；原运行完成清理后才可再次准入

#### Scenario: 全局容量或日配额耗尽

- **WHEN** 全局已有 2 个活动任务，或会话已达到新受理配额
- **THEN** 新请求分别返回 503 或 429，已存在请求的状态仍可查询和取消，不因被拒请求消耗更多配额

### Requirement: 恢复前确认单服务所有权

同一数据文件 SHALL 只由一个后端服务进程管理生成。启动恢复前 MUST 取得该服务的独占所有权；第二个健康竞争进程不得修改运行或监听。取得所有权后，遗留 running SHALL 在监听前标为 interrupted，保留消息、快照与当前版本，不重新调用模型；恢复无法落盘则启动失败。

#### Scenario: 崩溃后重新启动

- **WHEN** 原进程被硬终止，后续进程按既定所有权规则成功启动
- **THEN** 遗留运行可查询为 interrupted，旧当前版本和已完成候选保持不变，上游未被自动重新调用

#### Scenario: 同库启动第二个服务

- **WHEN** 原服务仍持有有效所有权，另一个进程以相同数据库和不同端口启动
- **THEN** 后者在恢复和监听前失败，不把原服务的运行标记为中断，不停止或修改原服务

### Requirement: 关闭顺序不会被活动流阻塞

正常关闭 SHALL 先拒绝新生成、中止活动请求并有界结束流，再关闭存储与释放服务所有权。清理期限内无法完成的运行 MUST 阻止晚到成功写入，并尽可能记录 interrupted；写入失败保持未确认，不谎报取消已保存。启动失败也必须释放本次已取得的资源。

#### Scenario: 等待模型时关闭服务

- **WHEN** 服务收到 SIGTERM 且存在活动 SSE 和上游请求
- **THEN** 在有限清理期内中止请求、结束连接并退出，不等待长连接自然结束；重启后原运行有明确终态或被恢复为 interrupted

#### Scenario: 清理期后收到晚到模型结果

- **WHEN** 受控上游忽略中止并在存储关闭后返回结果
- **THEN** 该结果不能提交候选或改变终态，不出现未处理异常或继续访问已关闭的存储

### Requirement: 流传输与缓冲有界

流 SHALL 使用标准 UTF-8 SSE 帧、禁止缓存/转换并提供周期性注释心跳；所有业务帧在编码前运行时校验。单帧最多 8 KiB，待发送积压和发送等待必须有界；慢消费者、超限或写入失败 SHALL 中止未完成运行并清理连接，不能无界缓存或不断生成事件。

#### Scenario: 慢客户端不读取流

- **WHEN** 客户端停止消费导致积压或发送等待达到上限
- **THEN** 连接和未完成生成被终止，内存缓冲保持边界，状态可另行查询，其他任务仍可完成

#### Scenario: 分块与心跳经过本地代理

- **WHEN** 浏览器通过 dev 或 preview 代理读取被拆分到多个网络块的 SSE
- **THEN** UTF-8、多帧和心跳被正确区分，业务序号有序，首帧与终态不被合并成完成后的单次响应

### Requirement: 状态与验证证据保持真实且最小化

状态响应、事件和错误 MUST 只向所有者提供必要元数据，不泄露提示词、代码正文、凭据、工具正文或原始异常。存储中仍为 running 但已无执行者时 SHALL 明确返回状态未确认，不伪装仍在执行。默认自动化以 fixture 验证真实网络/数据库边界，不声称真实模型、预览或最终服务器代理已通过。

#### Scenario: 无执行者且终态无法确认

- **WHEN** 存储保留 running，但该服务没有对应活动执行且无法确认终态
- **THEN** 查询与新生成返回安全的未确认/不可用结果，不显示虚假进度，也不启动新模型调用掩盖该状态

#### Scenario: 受控自动化与敏感错误

- **WHEN** 流式自动化使用含敏感哨兵的受控供应商响应
- **THEN** 事件、错误及日志不包含这些正文或凭据，报告标记 fixture；真实模型与最终部署验收继续保持独立状态
