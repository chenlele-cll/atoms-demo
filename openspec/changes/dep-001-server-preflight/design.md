# Design

## Context

范围见 [proposal.md](./proposal.md)。用户已确认私有 inventory 中密码的反斜杠为字面值，并授权 DEP-001 只读预检。尚不具备服务器版本、权限、工具链或访问端口的实测结论。

## Decisions

- 复用本机 OpenSSH，不安装 Ansible 或其他依赖；从权限 0600、Git 忽略的 YAML 配置读取连接值，不 source 文件或把密码放进命令行、环境值或日志。
- 首次使用本次私有 SSH_ASKPASS helper 向 OpenSSH 提供密码，只响应密码提示，限制一次密码提示和连接/命令期限。首次失败后，按用户要求用本机原生伪终端复核；用户反馈手动可登录后，再核对本机默认配置并允许其原有认证方式复现一次。每次至多一次密码提示，保留字面密码，不尝试变体或修改认证配置。
- 本机存在同一目标的 SSH 进程仅证明已有 TCP 会话；用户反馈登录成功单独记录，不能据此声明本次探针已认证或已运行。不能接管现有终端时，保留会话并请求对应服务端认证日志，不绕过工具访问限制。
- 仅为目标主机使用私有 known_hosts。有既有目标信任记录时保留，首次连接采用 accept-new 并记录首次使用的指纹；不关闭主机密钥检查，不覆盖已知不匹配的密钥，也不将首次观测声称为带外验证。
- 远端只运行白名单式版本、系统/资源/文件元信息、sudo 非交互能力、Nginx 状态/配置测试与监听端口检查。不读取应用环境、数据库内容或证书私钥，不安装、重载、重启或创建远端部署目录。
- 本机只对目标的相关公开端口做限时连接/TLS 检查，不调用业务写接口或模型。端口可达不代表 ACME、多地验证或完整 HTTPS 部署已通过。
- 详细环境与指纹仅记录在忽略目录 test-results/dep-001，目录 0700、私有证据 0600；公开工件只记录脱敏结论。预检缺失前提也应形成真实报告，后续修复归 DEP-002/003。

## Risks / Trade-offs

- 首次 SSH 信任没有独立提供的指纹 → 报告记录首次使用信任范围，后续对照持久记录，主机变化拒绝连接。
- 服务器可能缺少 Python 或查询权限 → 只报告未验证/待处理，不自行安装或索取更多权限。
- 安装版本和网络与本地不同 → 使用实际输出分类，不将其他环境结果充当本机上线证据。

## Migration Plan

无远端迁移或配置变更；本地临时认证 helper 完成后删除，保留无密码的私有预检报告。后续 DEP-002 根据实测前提准备部署框架。
