# Proposal

## Why

GEN-001～007 各自规划了必要测试，但还缺少一套能在同一输入版本上串行执行、定位失败并汇总证据的产品回归入口。`GEN-008` 整合现有检查和分模块验收，确保面试前能够重复验证工作台完整路径，而不是把零散通过记录或 fixture 当成真实模型与部署通过。

## What Changes

- 保留 `pnpm check`、`pnpm smoke` 及各模块独立入口，新增较短的 `pnpm verify:product`，并扩展既有 `pnpm verify`；两者使用同一固定执行计划，前后端生产构建一次，共享端口的检查串行。
- 产品配置覆盖工程/模板准备测试、现有 infra/诊断回归和从真实工作台发起的主路径；完整配置再执行 manager 及模板/项目/事件流/候选专项浏览器回归，不重新嵌套运行产品配置。
- 在明确的隔离源副本与数据目录验证，记录实际源码/构建身份；不读取开发者真实环境文件、数据库或模型凭据，不在工作副本制造故障，不调用真实模型探针或 live 生成入口。
- 为浏览器子套件接入统一、最小的结果摘要，记录通过/失败/环境阻塞/取消/未执行及证据关联；退出 0、打印 PASS、旧截图或空报告都不能单独构成产品验收通过。
- 明确缺前置条件、依赖网络失败、构建/断言错误、超时和清理失败的分类，失败停止后续执行且不自动重试；中断时只清理所属进程和临时数据，未知占用者保持不动。
- 将已有跨路径行为映射到拥有该断言的测试，补齐真正缺失的主路径连接和重复运行覆盖，不另建测试框架或复制每个模块已有用例。
- CI 默认质量检查复用产品配置，手动完整生命周期复用完整配置；仅上传白名单脱敏摘要/截图，配置验证和实际 hosted runner 结果分开记录。
- 本轮只生成规划，实施依赖 GEN-001～007 的实际测试入口；真实模型、最终访问地址和反代部署仍由 GEN-010、GEN-009 验收。

## Capabilities

### New Capabilities

无。本变更只增加工程验证编排、测试适配和证据汇总，不增加用户产品能力；使用 `.openspec.yaml` 的 `skip_specs: true`，不创建产品 spec。

### Modified Capabilities

无。复用既有生成、持久化、执行、候选和工作台规格作为测试依据；不改变公开 HTTP、生成/采用状态或业务规则。

## Impact

- 根工具：package scripts、固定套件计划、隔离 fixture、进程/报告辅助及控制测试；复用 Node 测试器、playwright-core、Chrome 和已有锁库，无新测试框架或外部基础设施。
- 各 smoke：必要的结果/路径/清理适配，保留独立运行和原行为断言；不通过测试专用产品开关替代真实实现。
- CI：现有 workflow 的入口、时间预算与 artifact 白名单；复用现有固定 Action 来源、只读权限和无应用 secrets 的规则。
- 文档：README、Verification 维护命令/覆盖/证据，Lifecycle 只更新实际隔离与清理变化；不新增平行任务清单或把上游未完成任务勾为已完成。
