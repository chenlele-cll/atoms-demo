# Context

原生 Process Compose 已验证双服务起停，但状态标签和上一轮退出码可能残留，持续未就绪也不保证自动清理。需要薄层命令把原生行为组织为用户已确认的生命周期契约。

# Goals / Non-Goals

- 目标：幂等 start/stop、可重复 restart、只读 status、跨命令互斥、实例归属、真实就绪及有界回滚。
- 非目标：自建守护器、自动装依赖或升级工具、完整 doctor、日志界面、基础设施、生产编排。

# Decisions

- shell 仅定位仓库并执行 Node 辅助入口。Process Compose 后台运行并拥有应用的重启、探针和日志；manager 命令执行完退出。
- 使用根精确开发依赖 `proper-lockfile@4.1.2` 的原子目录锁与心跳/过期处理，统一 stale/update 参数。修改操作有界等待锁；status 不等待修改锁，以便看到 starting。
- 仓库 realpath 决定实例域。状态写入忽略的 `.runtime/manager/`，短 Unix socket 放在当前用户、仓库路径哈希对应的私有 `/tmp/` 目录，避免深路径超长。同名目录非本人所有或为 symlink 时拒绝使用。
- 每个实例有随机认证值与原生项目名，持久状态原子写入且权限 0600，不输出认证值。启动前校验本地固定工具、Node/pnpm 和配置；不覆盖环境文件。外部占用端口时失败，不按端口杀进程。
- 用原生状态、当前进程树、原生端口归属及真实健康正文/前端代理共同判断就绪；不按 `Completed`、单个 `Ready` 或上一轮退出码判断健康。状态区分 stopped、starting、unready、healthy、failed，并提供 JSON。
- start 在固定整体期限内等待；已有健康实例不换 PID。已有未就绪实例先等待原生恢复，失败时停止所属实例并返回错误。restart 在同一锁内停止再启动，最终只有一组健康实例。
- stop 优先使用认证的原生停止 API；实例不可达时按已记录 PID、启动时间与命令身份识别所属进程树。仅在身份匹配时使用信号兜底，超时非零并保留可恢复记录；不删除数据、不操作未知 socket 或其他仓库实例。
- SIGINT/SIGTERM 中断启动时仍执行回滚并释放锁。崩溃后的锁由上游过期恢复，下一次命令核对持久实例记录；无法确认归属时明确失败，不扩大清理范围。

# Risks / Trade-offs

- 只承诺在所有修改命令使用同一 manager 的本地文件系统上串行执行；不同时混用原生命令修改该实例，不手动删除活跃锁。操作系统 PID 校验与发信号之间仍存在系统调用间隙，不将其描述为对恶意同用户程序的隔离。
- Node 辅助脚本需要已安装根依赖，固定 Process Compose 也需预先安装；自动 bootstrap 留到下一任务。POSIX、macOS arm64 实测，不宣称 Windows 支持。
- 两个仓库副本隔离控制状态，但固定应用端口仍互斥。进程外部硬杀、系统断电或损坏记录无法凭空恢复未知身份，应保留诊断并拒绝误杀。

# Migration Plan

保留原生配置与独立应用命令，新增 manager 后以它作为推荐本地编排入口。完成行为测试和文档交付；运行状态不随 Git 分发。回退只移除本任务文件、依赖和入口，先停止其所属实例。
