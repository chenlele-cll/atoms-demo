# Design

## Context

目录现状与动机见 [proposal.md](./proposal.md)。Codex 与 OpenCode 原生发现共享 .agents/skills，现有 Codex 版 OpenSpec 已同时说明两种调用形式。OpenCode 1.18.23 对个人同名技能的并行加载可能覆盖项目结果，单纯复制目录或额外配置重复路径不能保证优先级。

## Decisions

- 将 atoms-frontend-design 整个目录移动到 .agents/skills，保持正文与 references 字节不变；确认 OpenCode 生成副本仅有调用形式差异后删除，保留已有共享七个工作流与上游资源。
- OpenSpec 后续使用官方 codex,agents 目标。它们共享一个物理目录，沿用 codex 所有权 marker，官方兼容渲染同时保留 `$openspec-*` 与其他工具调用提示；不手改生成内容，不再选择 opencode 目标生成另一份技能。
- 不创建软链接、同步脚本或新项目依赖。新增不支持共享目录的宿主时，只使用其受支持的目录配置/必要链接适配，权威内容仍只有一份。
- 用户级配置与技能不迁移。分别验证 Codex 实际目录列表、OpenCode 共享目录的干净配置发现和默认配置结果；如存在个人同名冲突，记录实际来源，项目任务依 AGENTS.md 按权威路径加载。
- 当前文档统一引用新路径，历史已完成 change 保留当时的记录；本变更替代旧目录约定。工程与浏览器运行行为不变，不重复完整生命周期或 UI 回归。

## Risks / Trade-offs

- 不同宿主的发现与权限设置不同 → 明确仅验证当前可用宿主，不能将单一目录等同于所有未知工具均自动支持。
- 误删不同内容 → 逐文件核对上游正文与调用差异、保存忽略目录中的入口哈希及前像，遇到额外差异保留并处理。
- 刷新恢复两套副本 → 在隔离副本执行官方初始化与强制更新，核对共享文件、非 OpenSpec 技能及目录布局保持一致。

## Migration Plan

移动设计技能，移除已确认等价的工具专属副本，更新导航及刷新约定；需要撤回时依据本任务前像恢复，不影响其他任务或个人全局配置。
