# Proposal

## Why

当前后端没有模型配置、调用实现或能力验证，无法判断选定服务能否支撑后续代码生成。`GEN-002` 先建立单一供应商的后端调用基础，用可重复的探针验证文本、结构化文件输出与工具往返，避免将 SDK 兼容声明或测试替身当成真实接入成功。

## What Changes

- 建议以 OpenAI Responses API、`gpt-6.1-sol` 为首个验证组合，模型标识由后端配置显式指定；不因当前账户无权限而自动切换模型。现有 ChatGPT Pro 用于开发协作，不作为已准备好 API 凭据或 API 额度的证明。
- 延续 AI SDK 和 Zod 的既有选型，增加仅服务端使用的模型配置解析、单供应商客户端、调用时限与输出限制、取消及脱敏错误处理。
- 用户在实施中明确提供 `https://ai.elegantyc.com/v1` 的兼容 API 凭据并要求配置及实测；保持同一 Responses 协议与 gpt-6.1-sol，通过后端允许名单选择官方或该指定端点，报告实际服务，不增加认证或供应商适配框架。
- 提供本地命令行探针，分别验证真实文本响应、符合 schema 的小型文件集合、无副作用工具调用及结果返回模型后的最终响应。
- 自动化测试使用受控响应和本地 HTTP 测试服务，覆盖配置、协议、格式错误、认证、限流、服务故障、超时与取消；真实调用由单独探针命令执行，不接入默认测试或健康检查。
- 为源码和构建产物分别提供探针运行方式，记录脱敏的能力结果、耗时与供应商返回的用量；无凭据或未执行时明确报告未验证。
- 本次不增加公开模型接口、项目数据库、真实文件读写工具、Agent 生成循环、用户事件流、预览或完整 Top 1 验收；这些继续由后续 GEN 子任务承担。

## Capabilities

### New Capabilities

- `model-access`: 配置并调用单个后端模型，控制失败、超时和取消，通过本地探针区分真实模型能力与自动化替身测试结果。

### Modified Capabilities

无。当前没有已有的长期产品规格。

## Impact

- 后端：新增 `backend/src/model/` 中实际需要的配置、客户端、探针和能力样例，以及对应 `backend/test/` 行为测试；保持现有健康接口与服务启动不依赖模型凭据。
- 依赖：在后端声明固定的 AI SDK、OpenAI provider 和 Zod 版本，更新唯一 lockfile；不引入多供应商适配框架。
- 命令与说明：新增显式执行的探针命令及安全环境模板，更新模型配置、验证范围和使用前提；这些入口当前尚不存在。
- 前提：真实验收需要所配置服务可访问指定模型的凭据、额度及网络；官方 API 与兼容服务分别标明，不能以兼容服务通过推断官方 Platform 权限。只有用户明确要求后才执行真实探针，不自动充值。
- 其他接入方式：ChatGPT 套餐授权与 Codex SDK 不在默认实现中；它们涉及不同认证或执行边界，如改用该路线，先修订本提案。
