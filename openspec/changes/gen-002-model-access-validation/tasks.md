# Tasks

任务：`GEN-002`。范围为单供应商模型接入、能力探针和对应自动化测试，不包含真实项目生成。本轮仅创建规划工件，所有实施项保持未完成。需求见 [model-access](./specs/model-access/spec.md)，边界、参数与测试矩阵见 [design.md](./design.md)。

## 1. Configuration and dependencies

- [ ] 1.1 GEN-002 为 backend 固定 AI SDK、OpenAI provider 和 Zod 的兼容版本，更新唯一 lockfile；核对当前 Responses、结构化结果与工具接口并执行 frozen install，更新选型说明，前端不引入模型依赖。
- [ ] 1.2 GEN-002 实现调用边界的模型配置解析和安全环境模板，覆盖缺少/空白凭据、模型标识、时限与 token 限制；添加 Node 配置测试，确认未配置模型时既有 HOST/PORT 和健康接口测试仍通过，文档区分 Pro 与 API 前提。

## 2. Model client and capability cases

- [ ] 2.1 GEN-002 实现单 OpenAI Responses 客户端、文本及结构化文件样例，运行时检查拒绝、截断、schema、固定路径及体积；受控测试和本地 HTTP 集成验证实际请求模型、路径、`store: false`、输出限制及不执行/写入生成文件，并记录模块边界。
- [ ] 2.2 GEN-002 实现仅操作内存数据的 `inspect_fixture` 工具往返样例，限制两次模型请求和一次工具执行；测试真实工具分派、结果再次输入、最终确认，以及未调用、未知工具、非法参数与未确认的失败，证明不依赖 GEN-001 模板或项目服务。
- [ ] 2.3 GEN-002 加入零自动重试、完整样例截止时间、外部取消和统一安全错误分类；用延迟/失败的本地 HTTP 测试服务验证实际请求中止、晚到响应丢弃、后续步骤停止、认证/模型权限/限流/服务/网络错误，捕获日志验证哨兵密钥与原始错误体不泄露，更新错误说明。

## 3. Explicit probe commands

- [ ] 3.1 GEN-002 实现显式 `--case` 的源码探针 CLI、独立能力状态及脱敏报告，配置缺失标记未调用，`all` 只在三项通过时通过；添加受控报告和 CLI 测试，覆盖帮助无网络、部分失败/未执行、未知用量及实际请求上限，并文档化新命令。
- [ ] 3.2 GEN-002 加入构建产物探针入口和可选本地报告，处理 SIGINT/SIGTERM 及有限清理；子进程测试验证无凭据退出、帮助、信号处理及输出脱敏，检查 `node dist/model/probe.js` 的导入与运行依赖，并同步 README 和 Verification 的真实/替身验证边界。

## 4. Integration verification and handoff

- [ ] 4.1 GEN-002 运行 frozen install、`pnpm check`、`pnpm build` 和构建产物的无网络入口检查；确认默认测试、健康检查及现有本地总验收不会调用真实模型，不访问开发者秘密文件，记录退出结果并清理测试 HTTP 服务及子进程。
- [ ] 4.2 GEN-002 在 API 凭据、额度和模型权限确实准备好后，显式运行构建产物的 `--case all`，记录指定模型的文本、文件与工具实际结果、耗时及可用用量；如前提未满足或任何能力失败，保留该项未完成并报告具体边界，不能以替身测试通过代替。
- [ ] 4.3 GEN-002 核对配置、模型推荐、命令与实际实现一致，执行本 change 严格校验、链接和差异检查；在本清单记录实际能力与未验证范围供 GEN-004 使用，确认 GEN-001、manager、其他 change 和用户既有改动未被覆盖，不提交或推送。

## Workflow follow-up

- 本轮完成规划后停止；收到新的实施请求后，使用仓库 `openspec-apply-change` 工作流实施本 change。
- 如选择改用 ChatGPT 套餐授权、Codex SDK 或其他供应商，先修订本提案中的认证、调用限制及验收，不静默更换路线。
- 验证、规格同步和归档按后续请求分别执行；模型能力探针通过不能作为真实模板修改、持久化、预览或完整 Top 1 已通过的证据。
