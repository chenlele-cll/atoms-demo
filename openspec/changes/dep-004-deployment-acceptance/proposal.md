# Proposal

## Why

`DEP-004` 按用户请求验证真实部署的重复执行、代码/配置更新及失败数据保护，防止把命令返回成功或模板渲染当成上线验收。早期 DEP-003 尚未接入 apply、GEN-009 没有发布构建或产物，当时实际部署验收受前置条件阻塞；现已完成真实矩阵，见 acceptance-report.md。

2026-10-18 用户进一步明确本次只实现部署脚本框架，缺依赖可留待接入。DEP-003 框架可以继续，本变更的真实目标验收仍等待发布与执行接点；保留已完成的本地准备及所有待办。既有 acceptance-report.md 不代表新的服务器操作或验收通过，当前不提前发布构建。

后续 DEP-003 已补齐接点、GEN-009 已提供真实生产者；用户现明确要求继续完成 DEP-004 和端到端测试。本轮恢复实际只读 SSH/目标前提检查，通过后按矩阵执行真实部署。代码/本机测试完成不能替代服务器验收；自动 SSH 被目标拒绝时不对未知实例发布、停止或注入故障，不将电脑控制工具的 Terminal 访问限制当作脚本失败原因。

用户进一步要求使用 sshpass 实现密码自动化。本轮将部署入口改用 Ansible 官方 password_mechanism=sshpass，由上游通过匿名文件描述符传递 inventory 字面密码；补充控制端依赖检查与真实 sshpass/Ansible 行为回归，不自建 SSH 传输、不通过参数/环境明文传密、不自动改服务器认证。SSH 成功后继续原目标矩阵，失败如实记录。

## What Changes

- 建立对应 Lifecycle releaseId/数据保留规则的验收矩阵和可核对证据。
- 先执行只读前提与未实现入口保护检查；真实场景必须使用 DEP-003 最终部署契约、有效发布包和已确认归属的测试实例。
- 在前提就绪后实测重复部署、真实代码变化、独立配置更新、故障恢复、并发/中断及数据保留；未执行项明确保持待完成。
- 按用户后续要求默认同步本地私有 backend/.env 的非空模型设置，使用现有外置环境、配置指纹与幂等重启机制；显式补丁可替代来源，不将密钥放入发布包或公开证据。
- 用户实测 503 后补充发布包的真实配置解析门禁：拒绝配置与旧包不兼容，复用已实现的零超时逻辑构建新包并验证受理/取消，不调用计费模型。

## Capabilities

### New Capabilities

无产品契约变化；部署验收使用 skip_specs。

### Modified Capabilities

无。

## Impact

本轮维护验收工件与忽略的证据，修复真实 Linux 流程暴露的既有部署接点问题，并按用户要求补充自动模型配置来源；不另建部署器、发布格式或测试框架。前提缺失时不修改服务器、站点、认证、运行配置或数据库。实际故障演练仅操作归属明确的隔离验收实例，不触及其他站点或用户数据，不调用计费模型、不提交、推送或归档。
