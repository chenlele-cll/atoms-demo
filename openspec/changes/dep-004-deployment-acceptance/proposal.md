# Proposal

## Why

`DEP-004` 按用户请求验证真实部署的重复执行、代码/配置更新及失败数据保护，防止把命令返回成功或模板渲染当成上线验收。当前 DEP-003 尚未接入 apply，GEN-009 没有发布构建或产物，实际部署验收受前置条件阻塞。

2026-10-18 用户进一步明确本次只实现部署脚本框架，缺依赖可留待接入。DEP-003 框架可以继续，本变更的真实目标验收仍等待发布与执行接点；保留已完成的本地准备及所有待办。既有 acceptance-report.md 不代表新的服务器操作或验收通过，当前不提前发布构建。

## What Changes

- 建立对应 Lifecycle releaseId/数据保留规则的验收矩阵和可核对证据。
- 先执行只读前提与未实现入口保护检查；真实场景必须使用 DEP-003 最终部署契约、有效发布包和已确认归属的测试实例。
- 在前提就绪后实测重复部署、真实代码变化、独立配置更新、故障恢复、并发/中断及数据保留；未执行项明确保持待完成。

## Capabilities

### New Capabilities

无产品契约变化；部署验收使用 skip_specs。

### Modified Capabilities

无。

## Impact

当前新增本变更工件与忽略的本地证据，不另建部署器、发布格式或测试框架，不扩大 GEN-009/DEP-003 范围。前提缺失时不修改服务器、站点、认证、运行配置或数据库。实际故障演练仅操作归属明确的隔离验收实例，不触及其他站点或用户数据，不调用计费模型、不提交、推送或归档。
