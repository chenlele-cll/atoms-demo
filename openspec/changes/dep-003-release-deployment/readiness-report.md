用户已明确本次专注部署脚本框架，未实现依赖可以留作待接入点。无需提前 GEN-009 或接管核心功能；不另建打包器，也不继续等待发布前提来阻塞离线框架实现。完整产品和真实部署验收仍单独保留。

## Confirmed execution boundaries

待依赖明确后，按以下顺序落实本任务，实际任务复选框由 OpenSpec tasks 工件维护：

1. 复用 GEN-009 构建/校验实现，固定 release.json 契约；校验目标 Linux 系统、架构和 ABI，不上传 macOS 运行依赖。
2. 控制端选择匹配且完整的已有产物，无匹配才构建；发布 ID 不随重复部署或单独运行配置变化。
3. 校验服务器权限、已有 Nginx/服务归属、端口及 IP HTTPS；未明确之前不创建或覆盖站点。
4. 使用 Ansible builtin 管理独立目录、非 root 后端、外置配置及不可变发布包；持久数据不进入产物，已有模型配置不自动覆盖。
5. 停止已确认的所属旧服务并做冷备份/完整性检查，执行有停机的切换，验证后端、静态/API 代理及最终访问地址后才记录成功。
6. 相同产物/配置且健康时不重复切换或重启；失败保留证据与旧包，仅在数据库兼容时恢复旧包，不自动降级或恢复备份覆盖当前库。
