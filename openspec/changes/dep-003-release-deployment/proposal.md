# Proposal

## Why

`DEP-003` 将已提供的 Ansible 框架接入真实发布包、服务切换与失败恢复，使首次部署和后续更新遵守同一 releaseId/持久化边界。用户已要求执行本任务；开始时 GEN-009 发布构建仍为 0/10，没有发布包或稳定的实现层清单契约，DEP-001 自动认证尚未恢复。

2026-10-18 用户进一步明确：本次专注部署脚本框架，未实现依赖可以留作待接入点，不接管核心功能。本变更按此阶段范围继续，完成离线计划、Ansible 流程、配置暂存和幂等决策；发布构建、真实激活及目标验收另行保留。不提前 GEN-009，也不为框架验证连接服务器。既有 readiness-report.md 保留为此前检查快照。

## What Changes

- 新增离线 plan 与结构化输出，展示原生 Ansible 主流程、失败恢复与收尾，以及每个待接入点的任务归属。
- 用 Ansible import_tasks/block/rescue/always 建立阶段框架；提供真实 builtin 配置暂存，其他依赖以明确非零失败保留，不新增发布包格式或依赖复制器。
- 实现同包健康无操作、代码切换、配置单独更新和健康恢复的纯决策规则；实际状态读取、服务操作及备份兼容性仍为待接入点。
- 缺依赖时 apply 在私有配置读取和 SSH 前退出；本地验证不改服务器或核心实现，真实上传、激活、健康与失败恢复留待接入及 DEP-004 实测。

## Capabilities

### New Capabilities

无产品 HTTP 契约变化；工程部署使用 skip_specs。

### Modified Capabilities

无。

## Impact

涉及 deploy/、scripts/deploy.py、部署说明及任务证据，不修改产品或发布构建。框架阶段完成不代表真实发布完成；GEN-009、实际部署接入和 DEP-004 验收均保留。本任务不修改 SSH/密码/防火墙、目标站点或数据，不调用模型、不提交、推送或归档。
