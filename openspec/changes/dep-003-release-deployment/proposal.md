# Proposal

## Why

`DEP-003` 将已提供的 Ansible 框架接入真实发布包、服务切换与失败恢复，使首次部署和后续更新遵守同一 releaseId/持久化边界。用户已要求执行本任务；开始时 GEN-009 发布构建仍为 0/10，没有发布包或稳定的实现层清单契约，DEP-001 自动认证尚未恢复。

2026-10-18 用户进一步明确：本次专注部署脚本框架，未实现依赖可以留作待接入点，不接管核心功能。本变更按此阶段范围继续，完成离线计划、Ansible 流程、配置暂存和幂等决策；发布构建、真实激活及目标验收另行保留。不提前 GEN-009，也不为框架验证连接服务器。既有 readiness-report.md 保留为此前检查快照。

后续用户要求在依赖实现后复核第一批实现并补充完整。现已存在 GEN-009 发布构建/清单校验，本轮恢复实际执行接点，保留上述框架完成记录；补齐产物选择、目标构建、上传、私有配置、锁内激活/备份、健康和兼容恢复。仅做实现及隔离验收，不自动发布到真实服务器；真实目标结果继续单独记录。

## What Changes

- 保留离线 plan 和原生 Ansible 主流程，接点声明更新为实际实现状态；实现就绪和目标通过分别展示。
- 复用 GEN-009 验证器/公开源快照与真实生产者，接入显式 Linux 包、目标缓存/非 root 隔离构建和传输，不新增清单格式或发布构建器。
- 接入目标归属/工具/TLS、私有配置保留、跨操作进程锁、不可变发布、冷备份、原子切换、选择性服务更新和真实健康。
- 失败保留最近成功记录，兼容时恢复旧代码/配置，schema 不兼容时停止并保留现场供前向修复；不覆盖现库。本机实际 Node/Nginx/HTTPS/SQLite 与隔离故障验收完成后，真实目标继续由 DEP-004 验收。

## Capabilities

### New Capabilities

无产品 HTTP 契约变化；工程部署使用 skip_specs。

### Modified Capabilities

无。

## Impact

涉及 deploy/、scripts/deploy.py、部署说明和证据，以及生产者校验器原语的无依赖提取（接口不变），不改产品/依赖或重做发布构建。本机完成不代表 Ubuntu/systemd/公网目标完成；本轮不连接真实服务器、改其 SSH/密码/防火墙/站点/数据，不调用模型、不提交、推送或归档。
